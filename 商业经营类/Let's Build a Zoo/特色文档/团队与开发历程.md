# 团队与开发历程 — Let's Build a Zoo

> 开发商/工作室: Springloaded Pte. Ltd. (新加坡)
> 发行商: No More Robots (英国)
> 发行年份: 2021年11月5日 (PC) | 2022年9月29日 (主机)
> 平台: Steam / Epic / PS4 / PS5 / Xbox One / Xbox Series X\|S / Nintendo Switch
> 团队规模: 约5人核心团队

### 1.2 工作室历史

Springloaded 于 **2012年** 由 James Barnard 在新加坡创立（2013年7月正式注册）。Barnard 因对AAA游戏行业的"委员会式设计"文化感到幻灭而离开LucasArts，开始独自制作游戏。他原本预计只能坚持约8周就需要另找工作——但这一干就是十多年。

从2012年到2021年（Let's Build a Zoo发布前），Springloaded 主要制作手机游戏和小型项目。Let's Build a Zoo 是工作室**首款PC/主机大作**，也是真正意义上的突破性作品。

### 1.3 发行商

**No More Robots**（英国）是独立游戏发行商，创始人Mike Rose以发掘像素风和独立经营模拟游戏著称。双方的合作为Let's Build a Zoo 带来了关键的营销和平台资源。

## 2. 开发历程

### 2.1 开发周期

| 阶段 | 时间 | 说明 |
|------|------|------|
| 立项/原型 | 约2019-2020 | 从手机游戏转向PC/主机首作 |
| 主要开发 | 约2020-2021 | ~1-2年核心开发期 |
| Beta测试 | 2021年中 | Barnard连续5天观看Twitch主播试玩 |
| PC发售 | 2021年11月5日 | Steam + Epic Games Store |
| DLC 1 | 2022年5月26日 | Dinosaur Island |
| 主机发售 | 2022年9月29日 | 全平台 + Xbox Game Pass |
| DLC 2 | 2023年8月17日 | Aquarium Odyssey |

### 2.2 关键转折：Beta测试期间的发现

Barnard 在采访中透露，Beta测试期间的**Twitch直播观察**是开发中的决定性转折点。他连续5天观看玩家直播，发现最初的游戏设计有过于复杂的系统（如详细的储藏室/保质期管理），这些系统在纸面上合理但实际游玩时"挡在了乐趣前面"。

基于这些观察，团队**移除了过于复杂的子系统**，将"乐趣放在首位"（put fun front and center）。这是小团队的优势——可以在短时间内做出重大设计转向，而不像大厂那样需要经过层层审批。

### 2.3 技术决策

- **跨平台优先**：从开发第一天就为全平台设计，所有内容都支持手柄操作——这后来被证明是明智之举（主机首周即产生100万美元收入）
- **引擎**：使用Unity引擎（像素风2D游戏的主力引擎）
- **像素美术**：选择像素风不仅是美学决策，更是5人团队的生产力策略——像素精灵的变体开发成本远低于3D模型

## 3. 创意来源与设计哲学

### 3.1 灵感来源

| 灵感来源 | 借鉴了什么 |
|------|------|
| **Theme Park（主题公园）** | Barnard 的童年最爱——"建造一个地方，看人们在其中游玩"的核心体验 |
| **Cities: Skylines** | 反例——Barnard认为现代经营模拟"太复杂、太慢、缺乏幽默感" |
| **Forager** | 沙盒设计理念——"玩家不被锁定在任何选择中" |
| **现实动物园伦理** | "动物园是保育机构还是娱乐场所？"——这个无解的问题被转化为游戏中的道德双路线 |

### 3.2 设计哲学

Barnard 的设计哲学可以总结为三条：

1. **"趣味优先于真实"**：模拟经营不需要完全写实——如果"保质期管理系统"让游戏变慢就砍掉
2. **"道德不是标签，是经济模型"**：善与恶各自有完整的经济循环——道德不是贴在经营之上的装饰
3. **"小团队做大事"**：5人团队通过像素风+程序生成式内容（30万+CRISPR组合）实现了超越团队规模的内容量

## 5. 设计启示

### 5.1 对独立游戏开发者的启示

1. **小团队×像素风=高内容杠杆**：5人团队通过像素精灵+程序生成逻辑（CRISPR拼接）创造了30万+组合的"无限内容"，单位开发成本远低于3D游戏。像素风不是"复古审美"——在独立游戏中，它是**生产力策略**。
2. **跨平台优先从第一天开始**：Springloaded 从开发初期就为手柄操作设计——这让后来的多平台移植几乎零成本，主机市场贡献了与PC相当的营收。
3. **观察玩家比闭门造车重要**：Barnard 连续5天看Twitch直播后做出了"砍掉复杂系统"的决定——这个直觉重构如果发生在发售之后将不可逆。
4. **发行商选对了事半功倍**：No More Robots 在独立经营/像素风领域的发行经验让 Let's Build a Zoo 获得了Game Pass首日登陆——250,000+的曝光量是5人团队不可能独自获取的。

### 5.2 对商业经营品类的参考价值

1. **道德=完整经济循环而非装饰**：大多数经营游戏的道德系统是"多几个好评/成就"。Let's Build a Zoo 证明——如果要做道德，就做到能影响核心经济选择的程度，否则不如不做。
2. **收集驱动是经营游戏终局的最优解之一**：630个变异品种+30万种杂交组合——明确的收集清单给玩家"继续玩下去的理由"，解决了经营游戏经典的"科技树点完就无聊了"问题。
3. **科技树的"隐藏迷雾"设计可移植到任何经营游戏**：不是让玩家看到全部科技树然后规划最优路径，而是用迷雾覆盖→每次研究都像"翻牌"→惊喜感维持至游戏末期。

### 5.3 团队规模与游戏品质的关系

5人核心团队用约1-2年时间做出了一个销量10万+、Steam好评89%、Metacritic 78分的经营游戏。对比同品类的**过山车之星**（Frontier Developments，100+人团队）和**动物园之星**（200+人），Let's Build a Zoo 在内容深度/价格比上远超大型作品。这证明了——在经营模拟品类中，**精准的设计取舍比团队规模更能决定游戏品质**。
