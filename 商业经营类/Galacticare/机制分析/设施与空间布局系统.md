## 一、房间系统总览

Galacticare采用**拖拽式房间建造系统**——与双点医院相同的基本范式，但在空间主题和"设备组合逻辑"上有自己的特色。

### 1.1 房间类型

| 房间大类 | 子类 | 功能 |
|------|------|------|
| **接待/分诊** | Reception、Triage | 患者到达→登记→分配诊断 |
| **诊断室** | 多种诊断设备房间 | 确定患者的疾病类型 |
| **治疗室** | 多种专门治疗房间 | 针对特定疾病的治疗方案 |
| **研究室** | Research Lab | 解锁新技术、新房间、新设备 |
| **培训室** | Training Room | 提升医生技能等级 |
| **康复/观察** | Recovery Ward | 治疗后恢复观察 |
| **员工休息室** | Staff Lounge | 医生休息恢复 |
| **工坊** | Craftech | 设备升级和制造 |

### 1.2 治疗室特色（品类独有设计）

| 治疗室 | 治疗方式 | 设计风格 |
|------|------|------|
| **Boning Chamber（骨骼室）** | 3D打印替换骨骼 | 高科技+3D打印机 |
| **Dreamarium（梦境室）** | 触手外星生物治愈心理疾病 | 克苏鲁风可爱化 |
| **Projectile Medicine Room（投射药物室）** | 大炮发射祛痰药 | 军事+医疗混合 |
| **Centrifuge（离心机室）** | 旋转患者"以医疗的方式甩得很快" | 工业实验室风 |
| **Doctopus Tank（章鱼医生缸）** | 巨型章鱼进行处理 | 水生+医疗混合 |
| **远程接驳舱** | 治疗无法进楼的巨型患者 | 太空港+医疗混合 |

## 二、布局与建造机制

### 2.1 房间建造规则

| 规则 | 说明 |
|------|------|
| **最小面积要求** | 每个房间需要足够空间容纳所有必需设备 |
| **拖拽式建造** | 像双点医院一样，拖拽标签页中的房间类型到地面上 |
| **设备放置** | 房间大小必须能放下诊断/治疗设备+必要家具 |
| **复制粘贴** | 可快速复制已有房间布局——应对高峰期扩张 |

### 2.2 空间布局约束

| 空间维度 | 说明 |
|------|------|
| **走廊宽度** | Dyonai（高大物种）渴望宽阔走廊——需求驱动空间设计 |
| **天花板高度** | Dyonai渴望高天花板——影响装修选择 |
| **房间宽敞度** | Kouber Baly渴望大房间——需在空间效率和患者需求间权衡 |
| **院外空间** | 巨型患者通过接驳舱治疗——在医院外部需要专门的接驳区域 |
| **垃圾桶位置** | Xil物种渴望方便获取垃圾桶——位置影响患者流和行为 |

### 2.3 装饰系统

| 装饰类型 | 功能 | 物种关联 |
|------|------|------|
| 人类怀旧物品 | 满足人类患者"思乡"需求 | 人类 |
| 通用装饰 | 提升房间美观度评分 | 全物种 |
| 窗户/透明墙 | 满足部分物种的视野需求 | 待补充 |

## 三、动线与患者流

### 3.1 患者流线设计

```
入口 → 接待台(必须) → 诊断室A/B/C → [复诊?] → 治疗室X/Y/Z → 康复/出院
```

### 3.2 动线优化策略

| 策略 | 效果 |
|------|------|
| 接待台靠近入口 | 最小化第一步的步行距离 |
| 诊断室集群 | 多个诊断室相邻——减少患者在不同诊断室间的移动 |
| 治疗室就近诊断区 | 诊断→治疗的路径最短化 |
| 康复室靠近出口 | 治愈患者快速出院——减少不必要的院内滞留 |
| 员工走廊 | 员工专属通道减少与患者的动线交叉 |

### 3.3 与双点医院诊断链的差异

双点医院的核心动线是 **全科→专科诊断→治疗**，是一个线性升级诊断精度的过程。Galacticare的诊断系统更接近**多诊断室并行**模式——不同的诊断室可能检测不同维度的症状，而非逐步升级精度。

| 维度 | Galacticare | 双点医院 |
|------|:--:|:--:|
| 诊断模式 | 多室并行诊断 | 全科→专科诊断链 |
| 诊断确定性 | 中（需多室确认） | 中低（全科→专科逐步提升） |
| 空间策略 | 诊断室集群 | 全科近入口+专科分布 |

## 四、灾害与空间破坏

### 4.1 入侵事件

| 灾害类型 | 影响 | 应对 |
|------|------|------|
| **虫群入侵** | 破坏房间设备、影响美观 | 手动点击消灭→信用点奖励 |
| **陨石撞击** | 严重破坏房间、可能造成伤亡 | 紧急维修 |
| **外星病毒泄漏** | 污染区域、感染扩散 | 隔离区+紧急处理 |

### 4.2 灾害的空间策略意义

灾害系统让空间布局多了一层"韧性"考量——关键治疗室不应过于集中（一次陨石可能摧毁整个医疗服务链），医疗机器人(Medibot)的分布也需要覆盖所有高风险区域。

## 五、设计特点分析

### 5.1 "治疗室的奇幻想象力"

Galacticare治疗室的设计远超普通医院模拟游戏——3D打印骨骼、触手心理治疗、大炮投射药物、章鱼医生缸——这些都是对经典医院模拟"奇幻疾病+奇幻治疗"传统的太空升级版。每一间治疗室不仅是功能性房间，也是一个微观的场景设计。

### 5.2 "物种驱动的空间需求"

不同物种对空间的不同需求（宽走廊/大房间/高天花板）让空间规划从纯粹的效率优化变为**"为谁而设计"的人文考量**。这在医院模拟品类中是独特的——大多数同类游戏只有"病人"这一种匿名顾客类型。

### 5.3 与同品类对比

| 维度 | Galacticare | 双点医院 | 过山车之星 |
|------|:--:|:--:|:--:|
| 房间概念 | 太空奇幻医疗 | 搞笑现实医疗 | 游乐设施+商店 |
| 物种/类型驱动的空间 | ✅ 7物种 | ❌ 无差异 | ❌ 无差异 |
| 灾害空间策略 | ✅ 虫群+陨石 | ✅ 地震+流行病 | ❌ (天气) |
| 治疗室创意度 | ★★★★★ | ★★★★ | N/A |

## 六、设计启示

1. **治疗室的"主题化设计"是医院模拟的灵魂**：不只是功能房间，而是微型的叙事场景。3D打印骨骼室 vs 章鱼医生缸——患者期待"下一个治疗室会是什么样"本身就是游戏驱动力。
2. **物种需求驱动空间设计**让"装饰"不再是单纯的数值加成——而是具有世界构建意义的决策（"这是为Dyonai建的宽走廊"）。
3. **接驳舱远程诊疗**打破了医院经营游戏"所有患者必须进建筑"的天然假设——值得任何有"超常规体型顾客"的经营游戏参考。
