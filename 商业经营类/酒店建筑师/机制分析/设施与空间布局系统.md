## 一、建筑系统

### 1.1 从零建造

游戏允许从地基开始建造酒店：

| 建造步骤 | 说明 |
|------|------|
| 铺设地基 | 划定建筑占地范围 |
| 竖立墙壁 | 房间分隔 |
| 安装门窗 | 采光+通行 |
| 铺设地板/墙纸/天花板 | 装修品质影响房间价值 |
| 功能性设施 | 床、浴室、家具、设备 |

### 1.2 区域(Zoning)系统

房间通过功能区域标签定义其用途：

| 区域类型 | 功能 | 必需设施 |
|------|------|------|
| Guest Bedroom（客房） | 客人住宿 | 床+浴室+窗户(最低) |
| Bathroom（浴室） | 洗浴 | 淋浴/浴缸+马桶+洗手盆 |
| Restaurant（餐厅） | 饮食服务 | 厨房+餐桌+厨师 |
| Bar（酒吧） | 饮品+社交 | 吧台+调酒师+座位 |
| Kitchen（厨房） | 食物制作 | 灶台+冰箱+备餐台 |
| Gym（健身房） | 运动 | 健身器材 |
| Spa / Sauna | 放松/健康 | SPA设备/桑拿炉 |
| Conference Room（会议室） | 商务 | 会议桌+投影设备 |
| Laundry（洗衣房） | 后勤 | 洗衣机 |
| Maintenance（维修间） | 后勤 | 维修设备 |
| Lobby（大堂） | 接待 | 前台+等候区 |

### 1.3 多楼层建造

| 维度 | 说明 |
|------|------|
| 初始 | 单层建筑 |
| 楼梯 | 解锁多层→使用楼梯连接 |
| 电梯 | 研究解锁→提升客人/员工垂直移动效率 |
| 楼层切换 | PageUp/PageDown |

## 二、装修与美观度

### 2.1 定制系统

| 装修维度 | 可定制项 |
|------|------|
| 墙纸 | 多种图案/颜色 |
| 地板 | 木地板/瓷砖/地毯等 |
| 天花板 | 多种风格 |
| 家具 | 不同等级/风格的床、桌椅、装饰 |
| 配色 | 家具颜色可独立调节 |

### 2.2 房间价值计算

房间价值由以下因素综合决定：
- 房间面积（平方米/格）
- 家具数量与品质
- 浴室设施
- 窗户/自然采光
- 装饰密度
- 墙纸/地板等级

## 三、施工与物流

### 3.1 实时施工系统

与传统"点击即建造"不同，Hotel Architect有**真实的施工过程**：

| 施工要素 | 说明 |
|------|------|
| 施工队 | 雇佣建筑工人→他们物理搬运材料 |
| 材料站 | 在工地设置→缩短搬运距离→加速施工 |
| 工期 | 大项目需要游戏内时间完成 |
| 干扰 | 施工可能影响已入住客人的满意度 |

### 3.2 物流策略

- 材料站的位置影响施工效率
- 多施工队可并行建设不同区域
- 翻新/扩建需要在不影响运营的前提下进行

## 四、不同场景的空间挑战

| 地图 | 空间特点 | 核心约束 |
|------|------|------|

## 五、设计特点分析

### 5.1 "实时施工=建造即游戏"

让建造本身有施工时间、需要工人搬运材料——这不是繁琐，而是将"建造"从瞬间点击变为一个有策略意义的决策（"什么时候施工不会打扰客人？"）。这在经营游戏中的"即时建造"传统中是独特的现实主义取向。

### 5.2 "Zoning系统=灵活但有约束"

与双点医院的"预设房间类型"不同，Hotel Architect的Zoning系统更灵活——你划定区域后标签化→系统根据标签检查需求。这让房间设计更自由（可以设计不规则的豪华套房），但也需要玩家理解每个标签的需求。

### 5.3 与同品类对比

| 维度 | Hotel Architect | 双点医院 | 过山车之星 |
|------|:--:|:--:|:--:|
| 建造方式 | 实时施工(有工期) | 即时建造 | 即时建造 |
| 多楼层 | ✅ (楼梯+电梯) | ❌ | ❌ |
| 区域系统 | 灵活Zoning | 预设房间类型 | 自由放置 |
| 装修深度 | 高(每件家具可调色) | 中 | 极高 |
| 施工对运营的影响 | ✅ | ❌ | ❌ |

## 六、设计启示

1. **实时施工让"建造时机"成为策略决策**：不是"想建就建"，而是"什么时候建不影响客人"——为经营游戏增加了时间管理深度。
2. **Zoning系统在灵活性和约束之间找到了平衡**：比预设房间类型更自由，比完全无约束更有结构。
3. **多楼层+电梯解锁=垂直空间策略**：这是经营游戏中的稀缺设计维度——大多数同类游戏只有单层水平空间。
