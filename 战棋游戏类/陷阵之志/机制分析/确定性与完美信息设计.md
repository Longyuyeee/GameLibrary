# 确定性与完美信息设计 — 陷阵之志 (Into the Breach)

> 游戏版本: Into the Breach v1.2 (含Advanced Edition免费更新, 2022) | 平台: Steam/Switch/Netflix
> 数据来源: [Matthew Davis GDC 2019设计复盘](https://gdcvault.com/play/1026333/-Into-the-Breach-Design), [Game Developer访谈](https://www.gamedeveloper.com/design/-i-into-the-breach-i-dev-on-ui-design-sacrifice-cool-ideas-for-the-sake-of-clarity-every-time-), [GameLook中文摘要](http://www.gamelook.com.cn/2019/06/361390/)

## 一、品类最纯净的设计实验——"如果回合制战术没有任何随机性会怎样？"

陷阵之志是SRPG/战棋品类中最极端的设计实验：**完全确定性战斗**。没有任何命中概率、没有任何伤害随机数、没有任何暴击RNG。每场战斗开始时，所有敌方行动——移动目标、攻击目标、造成的伤害——全部完整显示在屏幕上。玩家的回合是："在已知所有结果的情况下，如何在4-5回合内保护城市？"

### 1.1 确定性公式

| 战斗要素 | 传统战棋 | 陷阵之志 |
|------|------|------|
| 命中率 | 70-95%（有MISS可能） | **100%确定**——武器伤害固定 |
| 伤害量 | 范围随机（如10-14） | **固定值**——武器显示"N点伤害" |
| 暴击 | 概率触发 | **不存在** |
| 敌方AI行为 | 半可预测（行为树） | **完全预知**——全部行动在回合开始前显示 |
| 环境/地形效果 | 概率触发 | **完全确定**——推到哪一格=伤害+位移确定 |

**设计哲学的来源**：Subset Games的前作FTL有大量RNG元素（导弹命中、事件结果、敌人生成）。设计师Matthew Davis说他们的核心原则之一是——在FTL中，有些玩家感觉失败不是自己的错。在陷阵之志中，**"every death feels like your own fault."**（每一个死亡都让你觉得是自己的错。）

## 二、预知攻击（Telegraphed Attacks）——全战棋品类唯一的100%信息透明

### 2.1 预知系统的工作方式

| 步骤 | 显示内容 |
|------|------|
| 敌方回合结束 | 每个敌人显示：**移动方向→攻击方向→伤害量** |
| 玩家回合开始 | **所有上述信息可见**——没有任何隐藏 |
| 玩家行动 | 基于以上信息做出所有3个机甲的决策 |
| 回合结束 | 所有预知的敌方行动执行（除非被玩家的推/拉/位移打断） |

**关键设计**：敌方AI的**目标选择**是随机的（哪个建筑/哪个机甲），但一旦选择，结果就**绝对确定**。这不是"概率确定"——是**完美的因果关系**：
- 一个攻击3点伤害的敌人→如果攻击到目标→目标恰好失去3HP
- 你把敌人推离一格→它的攻击目标从建筑变为空地→建筑免受伤害

### 2.2 与风花雪月/皇骑的信息透明对比

| 维度 | 风花雪月 | 皇骑重生 | 陷阵之志 |
|------|:--:|:--:|:--:|
| 命中概率 | 2-RN曲线（真随机但弯曲感知） | 近乎100%（重生调整） | **100%（完全确定）** |
| 伤害 | 固定公式但属性/技能影响 | 固定公式但属性/技能影响 | **武器固定伤害值** |
| 敌方行动 | 隐藏（AI行为树不可见） | 隐藏 | **100%预知** |
| 信息类型 | **概率信息**——"80%=大概率命中" | **半隐藏信息** | **绝对信息**——"3点伤害到那栋楼" |
| 玩家决策基础 | 概率+位置+资源 | 位置+资源+元素 | **纯粹解谜——已知条件+最优解** |

Davis说他们在开发中尝试过复杂的回合顺序规则和Timeline系统，但一年后完全废弃——"那些规则复杂但不深"。预知攻击的明确性产生了"真正的深度"。

## 三、核心目标逆转——保护建筑 > 击杀敌人

### 3.1 品类型唯一的胜利条件设计

在绝大多数战棋中，胜利条件围绕**消灭敌人**。在陷阵之志中，胜利条件围绕**保护建筑物**：

| 参数 | 说明 |
|------|------|
| 主要失败条件 | **电力网格(Power Grid)降至0**→永久死亡/游戏结束 |
| 电力网格减少 | 每次建筑物被摧毁→-1至-2电力 |
| 每场战斗的Grid HP | 4-7点（根据岛屿和难度）——最多可承受4-7栋建筑被摧毁 |
| 敌人会主动攻击建筑吗？ | **是——且AI优先攻击建筑而非机甲** |
| 机甲被摧毁 | 维修后可继续使用——**不会直接导致败北** |

**设计逆转**：你不需要杀死所有敌人——绝大多数战斗中你甚至不可能杀死所有敌人。你需要的是**操纵、位移和拖延**——让敌人攻击错误的目标。机甲是**消耗性资源**（HP可以在战后维修），建筑是**不可恢复的全局资源**（被摧毁后永久减少电力）。

### 3.2 为什么是建筑？

Davis在GDC复盘中的解释："在传统的战术游戏中，威胁来自敌人的攻击区域。预知攻击收窄了这些区域——所以我们需要新的威胁来源。答案是：**手无寸铁的平民建筑**。"

而更深的灵感来源是**超级英雄电影**——Davis觉得在那些电影中，整座城市被摧毁而没有人真正关心。他想要一个"你**必须**关心间接损伤"的游戏。

## 四、4-5回合——"如果我说我们会做一个4回合的战术游戏，我会说绝不可能"

4-5回合的短战斗不是预设的设计——是从确定性系统**自然涌现**出来的。Davis："因为确定性谜题从定义上是有限的、有解的——如果你给玩家无限的回合，他们总能找到最优解。限制回合数让每场战斗变得紧迫——你必须找到**好的**路线而不是**完美的**路线。"

### 4.1 回合压力的游戏效果

| 回合长度 | 效果 |
|:--:|------|
| 4回合 | 极度紧张——需要完美利用所有三个机甲的每个行动 |
| 5回合 | 标准——足够完成主要目标但不够解决所有小问题 |
| 额外回合 | 仅在特定任务中出现——给了更多自由度 |

## 五、设计启示——"清晰比酷炫重要"的设计纪律

Justin Ma（Subset Games的另一位联合创始人）总结了他们对UI和武器设计的哲学：
> *"As a game design principle, we would sacrifice cool ideas for the sake of clarity every time. If it can be shown in a clear way, [then] yes, we can have that."*

这把团队引向了一些艰难的设计决定：
- 只有**三种攻击类型**：火炮（Artillery）、近战/身体（Melee）、导弹（Missile）
- 所有范围攻击使用**仅直角模式**——玩家可以立刻看到任何敌人能命中什么
- 同类型敌人拥有**完全相同的属性**（相同HP、相同武器、相同移动力）——像国际象棋一样的可读性
- Davis承认砍掉了"我们真正觉得很酷的武器和攻击模式——因为玩家测试中没人能理解发生了什么"

**与风花雪月/皇骑高度复杂的系统形成了鲜明对比**——陷阵之志选择了一个相反的方向："少即是多。"
