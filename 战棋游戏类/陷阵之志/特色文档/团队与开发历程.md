# 团队与开发历程 — 陷阵之志 (Into the Breach)

> 开发商: Subset Games (2人团队) | 发行: 2018年2月27日 | 平台: Steam/Switch/Netflix
> 开发团队: Justin Ma + Matthew Davis (核心2人) + 作曲家Ben Prunty + 外包美术

## 1. 开发团队

### 核心二人组
| 角色 | 姓名 | 主要贡献 |
|------|------|------|
| **联合创始人/设计/美术** | Justin Ma | 像素美术、UI设计、视觉方向 |
| **联合创始人/设计/程序** | Matthew Davis | 编程、GDC复盘演讲者、核心系统架构 |
| **作曲家(外包)** | Ben Prunty | 与FTL同一位——电子+管弦乐的科幻曲风 |

**团队哲学**："Sacrifice cool ideas for the sake of clarity every time."（每次都为清晰度牺牲酷炫的想法。——Justin Ma）

### 从FTL到陷阵之志
Subset Games的前作**FTL: Faster Than Light**(2012)是独立游戏里程碑——太空飞船Roguelike——Steam好评95%+。FTL的开发过程中积累的经验直接塑造了陷阵之志：

| FTL教训 | 如何影响陷阵之志 |
|------|------|
| 部分玩家认为失败=随机数的错 | **完全确定性战斗——无RNG命中/伤害** |
| FTL运行一次需要1-2小时 | **全Run长度2-3小时——"午休内完成"** |
| FTL的成功验证了"小团队可以做大游戏" | 陷阵之志更紧凑、更精炼——"用设计约束创造深度" |

## 2. 开发历程

### 时间线

| 时间 | 事件 |
|------|------|
| 2012年 | FTL发布——获巨大成功(Steam 95%好评) |
| 2014-2015年(约) | 开始构思新项目——最初是"传统回合制战术游戏" |
| 2015-2016年 | **关键转折**——从"攻击系统"转向"预知系统"→废弃约一年多的传统战棋原型 |
| 2016-2017年 | "失败的战略层"实验——尝试XCOM式世界地图/科技树/文本事件→全部砍掉 |
| **2018年2月27日** | **正式发布**——Steam好评94%("Overwhelmingly Positive") |
| 2022年7月19日 | **Advanced Edition免费更新**——新增5支队伍、近40把新武器、7种新Vek、新驾驶员 |

### 重大设计挑战与如何克服

**挑战1: "传统战棋行不通"——第一年原型完全废弃**
Davis在GDC中说最初原型是标准PPEP回合制战术——有复杂的回合顺序规则和Timeline系统。但约一年后发现这些规则"复杂但不深"。转折点是**全面拥抱预知攻击**——从一开始就假设敌人行动是完全透明的。

**挑战2: "战略层完全失败"——第二年的大型系统被删除**
团队尝试了一年多的XCOM式世界地图——上面有资源管理、科技树、驾驶员关系系统、甚至文本事件。但三个致命矛盾迫使删除：
1. 确定性战斗限制了武器多样性→科技树变空洞
2. 巨型虫子的世界观中无法进行有意义对话
3. 战略层需要20+小时——与"短体验"约束冲突

Davis描述这是最痛苦的删除——"你花了一年的时间开发一个系统，然后意识到它必须全部被丢掉。"

**挑战3: 精简武器到三种攻击类型**
Justin Ma的UI原则导致了"只有三种攻击类型"的限制——即使团队喜欢很多更酷炫的攻击模式。Davis说他们砍掉了大量武器创意因为"玩家测试者根本看不懂"。

## 3. 技术与工具

- **引擎**：自研C++引擎——从FTL的代码基础演化而来
- **像素艺术**：8×8网格上的极简像素视觉——Justin Ma手绘所有机甲/Vek动画
- **配乐**：Ben Prunty的电子/管弦乐混合——与FTL的舒缓太空音乐形成对比，更紧急的"灾难即将降临"氛围

## 5. 设计启示

1. **"牺牲酷炫的想法以换取清晰性"**——Justin Ma的原则应用于每一处设计决策。
2. **"砍掉坏设计可以令人满足"**：Davis说认识到自己花了一年时间在错误方向上并不容易——但发布更好游戏需要的不是自负，是勇气。
3. **"设计约束创造深度"**：3机甲、8×8网格、4-5回合——不是限制，是定义。"如果我告诉你我们在做一个4回合的战术游戏，我会说'不可能。'但约束引导了设计。"
4. **"最小可行叙事"**：极简叙事可以与极深的机械系统共存——只要它们服务于同一个核心愿景。
