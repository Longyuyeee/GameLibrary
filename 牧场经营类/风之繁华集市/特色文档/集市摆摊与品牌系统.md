# 集市摆摊与品牌系统

> 范围：Marvelous《STORY OF SEASONS: Grand Bazaar》2025 重制版；手柄按钮及官方规则主要以 Switch 英文手册为准。非 NDS 原版或 Natsume《The Winds of Anthos》。本页是专题档案，不是全量验收，未执行实机。[返回游戏概览](../游戏概览.md) · [版本与开发历程](./团队与开发历程.md)

## 一、经济入口：日常商店和周六集市是两条路径

周六集市是本作的主节奏，不是唯一收入来源。官方城镇手册确认 Miguel’s Mercantile 等城镇商店可交易，店铺各有营业日与营业时间；集市则是把商品销售和整个市集的发展相连的独立场合。商店销售不能被默认计入集市考评；也不能推出所有商品在两渠道价格相同或集市必然卖得更贵。[城镇手册][town] [集市手册][market]

| 观察维度 | 传统每日出货箱（设计模型） | 本作的周六摊位（已确认） |
| --- | --- | --- |
| 周期 | 一批货每日进入被动结算 | 一周备货和加工，周六集中销售，分两场 |
| 库存 | 交货即进入结算队列 | 背包 → 拟售库存 → 台面陈列；陈列不等于已售 |
| 交互 | 把货交到统一入口 | 看客人要什么、要多少，站到对应货品前成交，主动摇铃招徕 |
| 营收 | 主要反馈货币或出货统计 | 每场看销售小结；次晨由评审核对集市的销售与摊位条件 |
| 出错与恢复（分析） | 下一天就能再试 | 周六错过一个场次仍可处理另一场；日常商店可作渠道对照，不代替集市成绩 |

这里不是断言星露谷、符文工房或动物森友会没有其他交易渠道。可复用的对照是：由玩家主动选择库存和站位，替代把货交给统一、被动结算的入口。不能把营收节奏的改变误解成「完全没有周内销售」。系列负责人中野魅明确说开发团队讨论后未采用自由定价；系统定价仍可因季节和游客等因素变化。[负责人访谈][interview]

## 二、一周准备与周六分场

| 阶段 | 操作与界面 | 决策看点 |
| --- | --- | --- |
| 周内 | 采集、耕种、养动物；把适当的原料送进风车。官方说明风大的日子风车加工更快 | 用加工完成时刻判断能否赶上出摊，不从季节单独推导风力 |
| 开摊前 | 去集市会场东北侧自己的摊位；从背包登记拟售库存，营业前可以调整；安排帐篷与装饰 | 「自己的摊位」是说明位置，不是任由玩家任选入口铺位的证据 |
| 第一场（周六 10:00 起） | 开场后在柜台按 Switch X 从库存陈列；客人报商品与数量，在对应商品前按 A 逐件成交；ZR 摇铃 | 记录主动招揽与自然到访，区别台面空、后台有货、库存耗尽与来不及结单 |
| 场间 | 开发组说明错过上午仍可做下午，空档可在附近逛店 | 在场间分别检查补货入口、可调装饰、能否换拟售库存；不把旧稿全部操作视为实装 |
| 第二场（周六 15:00 起） | 继续陈列、成交与使用声援；每场都会出销售小结 | 同一场次内先保留台面和库存变化，再比较两场效率 |
| 次晨 | Bazaar Review Board 发送评审；达标才升阶 | 销售与新摊位是两个指标；收摊当天看小结，不写成当晚自动升阶 |

Marvelous 日文发布稿明确确认两个场次分别于周六 **10:00、15:00** 开始；开发组确认场间有空档。未找到可确认每场结束钟点的官方文字；末尾保留了旧稿互斥口径，不把其中的结束时间写成正式数据。[官方集市图文][market] · [开发组周六说明][dev] · [Marvelous 周六开场时间及示意图][starts] · [官方风力介绍][site]

## 三、摊位陈列、营销与定价观测

[官方新版示意图：登记库存、开摊、上柜与摇铃][starts]。旧图路径属于原版站点，不用它证明重制版品牌。

**柜台和摊位库存分开。** 正常营业时从库存挑选上柜商品，再到顾客要求的商品位置执行成交；备货不等于全量都在台面。操作失败不必然说明商品不热门，也可能是台面补货或按键节拍受限。铃铛吸引未注意摊位的顾客，官方图文尤其提示附近已有多人时使用；目前无可采的通用客流倍率。[market]

| 变量 | 官方可证的作用 | 如何试验 |
| --- | --- | --- |
| 货品组合 | 玩家决定带什么和上柜什么；顾客有明确需求及数量 | 同一周、同一位置、同样装饰，用一组高数量单品与一组可比混售作对照，按 SKU 记成交账 |
| 装饰与帐篷 | 装饰可影响销售速度或快乐能量；与帐篷同系列累积效果，最多同时激活 3 项帐篷系列效果 | 逐次替一件，截录激活的效果；不要把上限「3」写成只能摆三件装饰 |
| 趋势 | 当季流行品卖得更快、售价更高 | 将成交速度和单价拆成两列；季节变化前后保持品牌、品质、新鲜度、场次与装饰尽量相同 |
| 报价 | 开发组反复讨论后保留系统定价，不开放玩家自由改价；季节和游客是负责人举出的变价场景。[interview] | 将「清库存／高毛利」落实为选货、陈列和取舍，不作为定价按钮；精确报价仍要逐场记录 |
| 渠道 | 城镇商店可买卖、玩家可以摆摊 | 用相同商品、星级、鲜度、品牌分别登记报价和实收；不假定价格之比为常数 |
| 其它增益 | 官方说明部分效果可影响卖货表现；不等于各类增益同时影响单价 | 将品质、品牌、鲜度、装饰、趋势、占卜、声援拆字段，逐项对照，不做无依据相乘 |

定价数据建议分 `displayed_quote`（显示）、`actual_gold_delta`（实际到账）、`item_count`（此次成交件数）。分析时以期初、期末差值校对，不以总场收入除去一项粗猜商品单价。没有实测，下面保留的旧稿倍率只作为检索线索。中野魅也以蔬菜摊为例说明可以通过摊位定制适配主售品类，并解释他们希望减少反复试价带来的压力；这不是取消经营选择，而是把选择转移到货品、装饰和销售时机。[interview]

## 四、品牌、比赛和加工：从证据强弱读结论

作品官方的[城镇手册][town]确认季节性的农作物与动物评选；作物品质更高、动物好感更好有利于评选。官方[牧场手册][farm]列出照顾动物与培养更高品质产物的联系。这些证据不能单独推出比赛后品牌售价公式，也不能把料理赛、赛马、作物赛采用同一认证规则。

一个公开的直接图证是[存栏动物状态界面截图][brand-cow]：界面上出现动物赛事金牌徽记，可作为「需记录比赛发生在什么层级、结果如何反映在状态栏」的调查证据。**金牌徽记截图本身不能测得倍率。** 有成体系的社区采集线索 [品牌说明与游戏截图][brand] 指向金阶农作物和动物比赛、原作物或副产物出现 `BRAND!` 标志；它所列固定约 ×3、青铜/白银提高品质上限、同类产品是否一同获标，以及标记加工后消失，仍要以同平台同版本存档复核。不要把比赛层级、商品品质上限、品牌状态和集市等级合并成一套 Rank。

| 核对题 | 样本设计 | 判定证据 |
| --- | --- | --- |
| 品牌给了谁 | 登记参赛单位、同品种或同货物类型的未参赛样本、赛前库存与赛后新产物 | 在库存详情截取标志，分「参赛个体、类型中其它个体、现存品、后续产物」四组 |
| 如何取得 | 分别留铜、银、金同赛事结算截图；作物赛与动物赛分开 | 同时写结果、奖章、星级上限与类型是否变化，不把「总夺冠次数」自动记成品牌等级 |
| 加工是否继承 | 原货留一份对照，将同批另一份拿去风车加工或烹饪 | 对比成品与原料的品牌标志、品质、数量与实收；无标记不等于成品价格一定低 |
| 是否影响市场或送礼 | 品牌和无品牌对照使用相同星级、鲜度、销售/送礼场景及其余变量 | 售价、顾客频次、声援、快乐能量和关系变化分别记，不从一个变化反推所有其它变化 |
| 料理与赛马 | 查对应赛事的规则、奖品及赛后状态栏 | 未确认品牌时维持未核，不把有获奖奖品误作商品认证 |

原料直卖与加工的工作示例（分析）：两颗同品种同品质作物中，一颗直卖，另一颗加工；同步记录投入是否一对一、加工完成时间、成品数量及各自未售件数。收益比较用实际到账减去额外材料和已观测的机会成本，另记是否错过场次。不使用旧稿「7 星卷心菜一定 8,000G+」当收入预测。

## 五、精灵声援：能力、量表和操作节奏

| 项目 | 手册或开发者确认 | 还须采集 |
| --- | --- | --- |
| 开放 | 推进到遇见 Nature Sprites 后可请它们组成声援团 | 事件名、准确触发条件和首开可参与成员 |
| 充能 | 卖货积累声援，充满至少一次可按 Switch ZL 开启；充满五次可获完整团队出力 | 各货物/数量换算、一次触发消耗、是否可跨场保留、超额处理 |
| 声援期 | 可用 Switch A 快速完成销售，柜台能以库存补货，也可从未陈列货品中补 | 时钟是否暂停、持续秒数、售卖选择顺序、无货时行为 |
| 成员差异 | 不同成员具有不同效果，等级越高效果越强；开发组举例品质与单次成交数量可变化 | 成员全名、位置、偏好及每级效果和适用品类 |
| 快乐能量 | 快乐商店使用 Happy Energy，而不是普通金币；官方列存储传送入口为商品例子 | 快乐能量和声援条是否同变量、各行为到数值的换算，不混作同一计量 |

证据：[集市手册][market] · [开发组集市专题][dev]。获取资料时可直接参照官方示意图中的[声援量表][cheer-img]与[开摊画面][open-img]；此处只登记官方页面的图片入口，未自行把图里读不到的数值视为事实。

**测试用小批量冲刺（分析，不是攻略收入承诺）。** 同品类两条线路先用相同备货充一次或多次量表，再决定在两段营业窗口的哪个点释放。固定摊位、帐篷与场次，比较前后动作数、游戏时钟差、成交明细和剩余库存，不用旧稿牧草 99、年糕 60 的写死配方。官方确认完整团队需要达到五次充满阈值，测试可对照只充满一次的最低可触发条件，但不要把这两种状态直接写成储存上限及每次消耗。

## 六、新鲜度、趋势与周转

趋势是季节销售状态，不等同于鲜度或品牌。官方确认季节趋势会影响销售快慢与价格，但没公开完整刷新表、条目池或统一 +30% 公式。鲜度是否影响「报价、成交概率、可参加作物展」属于不同命题。采用同一作物批次在同一场测，分别登记采收日、加工日、背包/储物/风车出品的文字或图标，后续再展开每种货品的时间规则。

| 对照 | 固定条件 | 记录值 |
| --- | --- | --- |
| 同日两种存放方式 | 品种、品质、品牌、出发日 | 储物前后鲜度与报价，是否中间进入过加工设施 |
| 早采或晚采 | 同一栽培条件与目标场次 | 采收日、首次品质/鲜度、当日报价和销量 |
| 原料或加工品 | 同批源货、相同等待时间 | 原料和成品各自鲜度标签；产出数与实收分开 |
| 趋势或常规 | 同一物品与尽可能一致的品质、鲜度和加成 | 季节趋势标记、销售间隔、单位价格；不预设必为 1–3 类 |
| 精灵是否延缓变化 | 相同物品与环境，按声援/成长状态分样本 | 是短时影响售价、改变鲜度标签，还是无可观察差异 |

## 七、集市成长：销售与摊商的双门槛

次晨评审不是单一资金计数器：官方明确同时看集市总销售额和摊位总数。集市知名度提高后吸引更多顾客及有意进驻的摊主；帮助摊商解决入驻问题，才能把潜在供给变成实际摊位。摊商增加又会带来各类商品和装饰，改善后续运营。Marvelous 举例，营业中的工务店可用钱扩田、加盖动物小屋、扩容背包；这些回馈能增加生产和带货能力，但公告不提供价格或前置公式。[market] [site] [starts]

建议将下列数据按不同主键保存，不互相推定：

| 数据表 | 一行代表 | 最小证据 |
| --- | --- | --- |
| 等级要求 | 某版本的某一集市阶位 | 评审目标截图，销售额及摊位数分列 |
| 自营摊位扩建 | 某阶段/订单后的可用陈列位与规格 | 进入前后柜台、帐篷界面，登记付费和任务 |
| 新店入驻 | 一名摊商或一间店的进驻条件 | 任务委托、完成确认及首次出现的日程 |
| 内容解锁 | 工具、风车、装饰、店铺或章节的一项变化 | 对应请求或日志；区分它是否由集市等级直接触发 |
| 实际晋级耗时 | 可回放的具体档案路线 | 平台版本、游戏起始日、评审日、漏周与回读记录；不从一条存档概括普遍用时 |

## 八、复盘：卖得好但没升级，先查哪一项

1. 读取次晨评审，先分清「营业额缺」「实际摊位缺」或两者都缺。
2. 营业额缺时核对两场销售小结。若带了足够库存却频繁空柜，先处理陈列或声援时机；若人少，比较摇铃与当季货品；若客户找到产品但很少成交，记录动作、数量与各项效果再定位。
3. 摊位缺时改去检查待入驻商、请求和实际开张，不靠同一种高价商品继续冲一个已达标的指标。
4. 保留一个只卖镇店的渠道对照，记录货币与评审的分开变化。时段、关闭机制和未售物去向按场次实拍，而非回填旧稿。
5. 设计启发：把周六作为消费高峰能拉开生产与销售的节奏差；加入第二条销售渠道可供周内调整，双门槛又保证把全市集建设纳入成长。调试时则应让玩家看见「库存、成交、摊商」三个约束，而不是只显示总收入。

## 九、旧稿档案：待核或已否定，不是游戏规则表

下表保留 c594460 被替换前的研究线索，便于逐条复查。**冲突/否定**表示旧说法内部矛盾或已与更高可信度来源冲突；**待核**不是采信，数值绝不能引用回机制正文。原稿有价值的设计问题已在上文重新展开。
