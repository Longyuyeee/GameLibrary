# 寿司店经营系统 - 潜水员戴夫(Dave the Diver)

> 游戏版本: Dave the Diver v1.0+ (PC/Switch, 2023年)
> 数据来源: NoobFeed Restaurant Guide, Casual Game Guides, IGN

## 1. 菜单设计

| 要素 | 说明 |
|------|------|
| 设置时间 | 每晚营业前 |
| 核心策略 | **味道>价格**→好味道=更多顾客=更高Cooksta评级 |
| 多样化 | 尽可能供应多种菜品(利用库存) |
| 实际库存 | 只上菜单有足够食材的菜品 |

> **菜单校订**：「多样化」与第六节「紧缩菜单」并不互斥。主菜可集中在少数高价品项，尾段用一份一出的备用菜补不足；别为填满菜单槽预做整批。见[七单对照](#82-七单对照多赚-357-g-还是留住食材)。

## 2. 营业操作

| 操作 | 效果 |
|------|------|
| 送餐 | 快速送到对应桌子 |
| 倒茶(Green Tea) | **完美倒茶=最高金币** |
| 清理桌子 | 客人离开后→腾出空位 |
| **补充芥末(Wasabi)** | **芥末耗尽=不能做任何菜!**——最优先! |
| 红条顾客 | 等太久→红条满→离开→**降低Cooksta评级** |

## 3. Cooksta评级系统

| 等级 | 解锁 |
|:--:|------|
| 铜(Bronze) | 基础 |
| 银(Silver) | 更多菜单位/新食谱 |
| 金(Gold) | 更多员工位/新食谱 |
| 白金(Platinum) | VIP客人 |
| **钻石(Diamond)** | **全部解锁** |

- 获取: 高味道评分+快速服务
- Artisan's Flame: 每夜评星→用于**研究新食谱**

> **晋级口径**：口味和服务是旧档的方向性总结，不是晋级公式。Cooksta 分别检查粉丝（点赞）、最高味道和已研究食谱数。钻石的 375 最高味道和 32 道研究食谱在[旧社区表](https://dave-the-diver.fandom.com/wiki/Cooksta)与[注明采样版本的社区记录](https://meowdb.com/db/dave-the-diver/cooksta)中一致；粉丝门槛分别为 720 与 1,050（后者标注 Steam Build 25315876），目标版本以游戏内手机界面为准。同一份[热带鱼寿司套餐食谱](https://dave-the-diver.fandom.com/wiki/Tropical_Fish_Sushi_Set)的最高味道为 346，距 375 差 29，不能因为卖价高就当作冲钻石的味道菜。

## 4. 菜品强化(Enhance)

- 永久提升**味道+价格**(不影响原料成本)
- 优先: 基础高销量菜品(蓝唐鱼/水母/鹦鹉鱼)
- 策略: 专注强化1-2道主力菜品→不要太分散

## 5. 食谱获取

| 类型 | 解锁方式 |
|:--:|------|
| 基础 | 捕获对应鱼→自动解锁(1种食材) |
| 剧情 | 主线推进 |
| Cooksta | 新评级+Artisan's Flame研究 |
| Boss | 击败Boss(已满级→无需研究) |
| VIP | 限时VIP客人服务 |
| 员工 | 员工Lv5/10/15→解锁特色食谱 |
| 活动 | 限时活动(黄瓜派对/金枪鱼派对等) |

## 6. 金币策略

| 策略 | 说明 |
|------|------|
| **紧缩菜单** | 1-2道高价值菜→稳定供应 |
| **强化优先** | 先强化主力菜→再扩展菜单 |
| 活捉=更高利润 | 3星完美捕获→更多肉+更贵价格 |
| 复盘数据 | 查看每夜统计→最佳菜品→针对性捕鱼 |

## 7. 设计特点

1. **菜单设计=库存管理**: 不是"有多少卖多少"——而是"只上今晚供应得起的菜"——库存不足=菜单失效
2. **芥末=最核心的资源**: 芥末=能做菜的能力——芥末耗尽=全厨房停摆=顾客愤怒
3. **Cooksta=社交评级**: 类似餐厅的Yelp评分——不是"赚多少钱"而是"好评多少"
4. **强化=长期投资**: 永久提升——不是"换更好的菜单"而是"让基础菜越来越强"

## 8. 自动供应、整批补料与闭店损耗

> **范围**：班乔寿司主店，Windows Steam [v1.0.6.2132（Build 26581443，2026-11-11）](https://steamdb.info/patchnotes/26581443/)为复测目标。补丁、社区记录和下列算例分开；未跑实机。

### 8.1 菜单上的一批不等于客人手里的一盘

[Mintrocket 2023-07-05 热修](https://steamdb.info/patchnotes/11631880/)确认菜单有 Auto Supply，并修过把剩余原料误显示成强化所需鱼量的问题。它没有规定补料时点。[菜单实操资料](https://davethediver.net/en/guides/how-many-sushi-servings/)与[早期操作记录](https://www.gametruth.com/guides/dave-the-diver-auto-supply-guide-using-fish-efficiently/)记载，选中已上菜单的菜，经「管理（Manage）」给该菜启用自动供应，原料足够时可按新的一整批补料。**没有投进菜单的原料可留到以后，已备但闭店未售的盘数会丢弃。** 最后一盘售出就触发、还是等新需求才补，留给目标版本对照；不能把自动供应等同于零损耗。

| 计量项 | 记什么 | 易混之处 |
|---|---|---|
| 储藏原料 | 鱼肉、米等还未投入的数量 | 强化和做菜都可能动到同一库存 |
| 配方批数 | 这晚准备了几次完整配方 | 一批可出多盘，不是客人点了几次 |
| 可卖盘数 | 每批盘数 × 已备批数 | 销量和闭店剩盘分别记；菜单容量不是到店需求 |

### 8.2 七单对照：多赚 357 G 还是留住食材

按[热带鱼寿司套餐（Tropical Fish Sushi Set）表](https://dave-the-diver.fandom.com/wiki/Tropical_Fish_Sushi_Set)及[配方用量](https://davethediver.net/en/recipe/tropical-fish-sushi-set/)，Lv.1 每批用 Titan Triggerfish、Harlequin Hind、Coral Trout 和米各 3，出 6 盘，售价每盘 375 G、味道 130。Lv.10 的做菜用量不变，出 9 盘、每盘 1,387 G；升级时额外消耗的原料不算每批用量。[Harlequin Hind Sushi](https://dave-the-diver.fandom.com/wiki/Harlequin_Hind_Sushi) Lv.1 用同名鱼肉 1，出 1 盘，售价 18 G。

| 方案（固定成功出餐 7 单） | 实际备餐 | 合计售价 | 闭店余盘 |
|---|---|---:|---:|
| 7 单都卖套餐 | 套餐 2 批，共 12 盘 | 7 × 375 = 2,625 G | 套餐 5 盘 |
| 前 6 单套餐，末单用单盘菜 | 套餐 1 批 + 单盘寿司 1 批 | 6 × 375 + 18 = 2,268 G | 0 |

第二种做法少收 357 G，却保留 Titan Triggerfish 3、Harlequin Hind 2、Coral Trout 3 和米 3，相当于晚间为了提高一单卖价，需要用掉这些原料。只比菜品销售额，不含小费、成本或明日用料价值；假设第七单能改卖备用菜，不是对顾客选菜的预测。若预估只剩一两单、做菜材料又要留给次日委托，我会先保原料，不把大份菜挂自动供应；给备用菜单独开自动供应时仍可能多补一盘，不能直接套用表中零剩余。

### 8.3 复测：最后一盘售出后，什么时候扣下一批原料

1. 复制同一晚开门前存档，固定主店 Cooksta 评级、员工、时段、菜品等级；主菜只备一批，仓储留足至少再做一批的四种原料，关闭其他自动供料菜。记录初始原料和盘数。
2. 两次只切换主菜 Auto Supply 开/关。分别在第六盘交付前、已无待处理套餐单的时刻、第七单出现后记录库存与盘数。如第七单太早出现、拉不开时间，另测一晚，不用该次判断触发顺序。
3. 临近闭店再做一次，用单盘菜作独立对照，记录「原料扣除」「菜单增加」「售出」「闭店丢弃」的顺序；不把暂停画面中的等待当成游戏时钟推进。
