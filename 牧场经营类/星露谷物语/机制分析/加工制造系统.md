## 1. 数据归属与系统边界

旧文档把机器产出、制作配方、农场建筑、房屋升级和法师塔建筑混在一处，并用“常用”“高价值”节选代替全集。PC v1.6.15 重构后采用三个唯一数据源：

| 数据集合 | 唯一数据文档 | 全集口径 | 本机制文档的职责 |
|---|---|---:|---|
| 加工机器 | [加工配方数据总览](../数值数据/加工配方数据总览.md) | 工匠 10 + 精炼 20 = 30 台 | 解释输入、计时、输出和布局循环 |
| 烹饪配方 | [烹饪配方数据总览](../数值数据/烹饪配方数据总览.md) | 81 条 | 解释厨房、解锁、增益与库存联动 |
| 制作配方 | [制作配方数据总览](../数值数据/制作配方数据总览.md) | 150 条 | 解释资源转化、配方解锁与设施扩张 |
| 农场建筑/房屋升级 | 不属于本数据域 | 后续在建筑与升级域单独对账 | 仅讨论其对生产空间的影响，不复制造价表 |

这样处理的核心是“一个数字只有一个权威落点”。机制分析可以链接到数据表，但不再维护第二套售价、材料或配方清单；源数据更新时，只需重新运行生成器和审计器。

## 2. 加工机器的统一循环

大多数机器都可以抽象为四段状态：

```text
获取机器/配方 → 投入符合条件的物品 → 等待机器规则结算 → 收取产物并重新装填
```

| 状态 | 系统检查 | 玩家决策 | 数据入口 |
|---|---|---|---|
| 解锁 | 技能等级、任务、精通、商店或房屋条件 | 先解锁高周转还是高单价设备 | [30 台机器快速索引](../数值数据/加工配方数据总览.md#机器快速索引) |
| 装填 | 输入 ID、标签、数量、地点和机器是否空闲 | 原料直接出售、加工或保留 | [Modding:Machines 规则](https://stardewvalleywiki.com/Modding:Machines) |
| 处理 | 分钟、夜晚、天气、季节、地点等条件 | 批量同步还是错峰运行 | [逐机固定页记录](../数值数据/加工配方数据总览.md#machine-bee-house) |
| 收取 | 固定产物、随机池、品质/价格修正、再触发 | 立即卖出、陈酿、烹饪或再加工 | [小桶](../数值数据/加工配方数据总览.md#machine-keg) / [木桶](../数值数据/加工配方数据总览.md#machine-cask) |

1.6 的机器数据允许用输入物 ID、上下文标签、数量和游戏状态条件匹配规则；输出可以复制颜色、品质或价格，也可以使用固定产物、随机产物或专门方法。这解释了为何“机器都是放进去再等待”只是表面相似，实际计算路径并不统一。

## 3. 时间、条件与产出模型

### 3.1 四种常见计时方式

| 模型 | 典型设备 | 设计效果 |
|---|---|---|
| 游戏分钟倒计时 | [压酪机](../数值数据/加工配方数据总览.md#machine-cheese-press)、[熔炉](../数值数据/加工配方数据总览.md#machine-furnace) | 适合一天内多轮操作，奖励高频回访 |
| 跨夜/按夜结算 | [蜂房](../数值数据/加工配方数据总览.md#machine-bee-house)、部分被动产出设备 | 将生产与睡觉循环绑定，降低精确卡点压力 |
| 天气或地点条件 | [太阳能板](../数值数据/加工配方数据总览.md#machine-solar-panel)、蜂房 | 让地图和天气成为生产参数 |
| 长周期品质提升 | [木桶](../数值数据/加工配方数据总览.md#machine-cask) | 用空间和资金周转换取更高终值 |

分钟不是现实分钟，也不能简单除以每天可操作时长得到“自然日”。跨夜机器、暂停条件和只在夜间完成的规则必须以各固定页为准。旧文档中“约几天”的口语换算已经移除，避免把不同计时模型混为一谈。

### 3.2 固定、公式与随机产出

| 产出类型 | 示例 | 风险/收益特征 |
|---|---|---|
| 固定输入→固定输出 | 奶、矿石等基础加工 | 容易规划库存和设备比率 |
| 输入价格派生输出 | 果酒、果酱等保藏品 | 原料价值会放大，机器槽位成为稀缺资源 |
| 输入标签决定品类 | 水果、蔬菜、鱼、蘑菇等 | 一个规则覆盖大量物品，必须按完整标签集合核验 |
| 随机池与概率 | [碎骨机](../数值数据/加工配方数据总览.md#machine-bone-mill)、[种子生产器](../数值数据/加工配方数据总览.md#machine-seed-maker) | 期望值有意义，但单次结果不保证 |
| 环境决定输出 | 蜂房附近花卉、蘑菇树桩周边树木 | 布局本身成为“配方”的一部分 |

## 4. 价值、品质与机会成本

“售价更高”不等于“应当加工”。正确比较至少包含五个变量：

| 变量 | 问题 |
|---|---|
| 原料机会成本 | 原料能否直接出售、送礼、完成收集包或用于另一条配方？ |
| 槽位时间 | 同一台机器在这段时间还能处理什么？ |
| 品质规则 | 输入品质会被忽略、复制，还是影响输出？ |
| 职业修正 | 工匠等职业是否作用于最终产品？ |
| 二次加工 | 产物能否继续陈酿、烹饪或制作？ |

因此，策略判断应使用“单位机器时间新增价值”，而不是只看最终售价。高价原料通常适合倍率型机器；低价、高产、短周期原料可能更适合快速机器或直接出售。所有实际输入、输出、价格和时间都应从[加工机器全集](../数值数据/加工配方数据总览.md)读取，避免机制文档复制后失去同步。

## 5. 烹饪系统

烹饪在第一次农舍升级获得厨房后开放，也可以通过野炊工具在外部进行。厨房把背包、冰箱和迷你冰箱视为可用原料池，形成“长期储备—临时选餐—消耗增益”的循环。

| 机制层 | 关键规则 | 完整数据入口 |
|---|---|---|
| 配方学习 | 初始、电视、友谊邮件、技能、商店和其他事件 | [81 条来源与解锁条件](../数值数据/烹饪配方数据总览.md) |
| 原料读取 | 背包、冰箱、迷你冰箱共同参与 | [81 条中英文原料](../数值数据/烹饪配方数据总览.md#group-1) |
| 食物增益 | 新食物增益替换当前食物增益 | [各配方 Buff 与时长](../数值数据/烹饪配方数据总览.md#group-1) |
| 饮料增益 | 饮料与食物分开处理，可以并存 | [Cooking 固定页](https://stardewvalleywiki.com/mediawiki/index.php?title=Cooking&oldid=193813) |
| 齐氏调味料 | 改变品质、恢复值、价格、部分增益与持续时间 | [Cooking / Qi Seasoning](https://stardewvalleywiki.com/Cooking#Qi_Seasoning) |

烹饪的设计价值不只在恢复生命和体力。它把作物、鱼类、采集物、畜产品、商店原料和社交解锁汇入同一系统，使玩家保留多样库存而不是只种单一最高收益作物。

## 6. 制作系统

PC v1.6.15 的 150 条制作配方跨越炸弹、围栏、洒水器、设备、肥料、种子、装饰、钓鱼、戒指、消耗品、照明、存储等 17 个展示分类。完整清单及每条原料、产量和来源见[制作配方数据总览](../数值数据/制作配方数据总览.md)。

### 6.1 解锁来源

| 来源 | 系统作用 |
|---|---|
| 初始配方 | 保证开局具备基础存储、照明、通行与农场边界能力 |
| 技能升级 | 把生产能力作为成长奖励逐级释放 |
| 友谊和邮件 | 将社交进度转化为功能性收益 |
| 商店购买 | 提供金币换知识的资源回收口 |
| 任务/特殊订单 | 把新设备与中长期目标绑定 |
| 精通与后期区域 | 延长终局的生产扩张曲线 |

原始配方数据的解锁字段不包含所有硬编码来源。例如若干开局配方、地窖解锁木桶、事件跳过后的配方补发由代码处理。因此全集同时保留“原始解锁条件”和中英文展示页的“玩家可读来源”，不能只用其中一层。

### 6.2 工作台与批量制作

工作台会读取相邻普通箱子和大箱子的材料，使“整理库存”转化为“生产基础设施”。这降低了 150 条配方带来的背包管理成本，也让生产区布局不只是摆放更多机器，还包括原料可达性和补货路径。

## 7. 生产布局与节奏

| 阶段 | 主要约束 | 推荐思路 |
|---|---|---|
| 前期 | 铜、铁、煤炭、木材和金币都紧缺 | 先满足浇水、存储和任务，再扩展低成本加工 |
| 中期 | 原料产量增长快于机器数量 | 按作物收获周期配置加工槽位，保留应急直接出售渠道 |
| 后期 | 空间、装填时间和运输成为瓶颈 | 用小屋、路径、箱子和批量同步减少操作成本 |
| 终局 | 追求完美、全制作、全烹饪和高价值库存 | 以配方完成度和缺失材料反推生产，而非只看金币 |

自动化在本作中是渐进而非彻底的：料斗可以供料但不会替玩家收取大多数产物；祝尼魔小屋解决部分收获，却不自动完成整条加工链。设计保留了玩家“每天巡视农场”的触点，同时允许用布局降低重复劳动。

## 8. 设计特点与同类对比

### 8.1 与《牧场物语》系列对比

《星露谷物语》把大量设备配方分散到技能、社交、任务、商店和后期区域，而传统《牧场物语》作品通常更集中于农场设施升级或商店购买。前者让几乎所有成长线都能回馈生产系统，代价是配方来源更难靠记忆管理，因此完整可检索的数据表尤其重要。

### 8.2 与《波西亚时光》对比

《波西亚时光》的制造更接近多级工业流水线，玩家经常需要中间件套中间件；《星露谷物语》的单机规则相对短，复杂度主要来自原料季节性、机器槽位和日历。两者都奖励产线规划，但一个偏配方依赖图，一个偏时间与机会成本。

### 8.3 与《Graveyard Keeper》对比

《Graveyard Keeper》的技术树和工作站区域分工更强，错误投资可能长期卡住流程；《星露谷物语》允许直接出售、购买原料或暂时跳过加工，失败惩罚更柔和。这种“有最优解但不强制最优解”的结构，是本作兼顾休闲与深度的关键。
