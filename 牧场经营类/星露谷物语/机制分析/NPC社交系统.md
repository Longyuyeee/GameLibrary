## 二、社交系统的四层结构

### 2.1 名册层

官方 Villagers 名册包含 46 名人物，其中 34 名可接受常规礼物，12 名属于不可送礼人物。34 名可送礼居民又分为 12 名婚恋候选人和 22 名非婚恋居民。

名册层决定“谁拥有关系数据、谁能送礼、谁可进入恋爱或室友状态”。完整中英文名、生日和身份见 [NPC数据总览](../数值数据/NPC数据总览.md)。

### 2.2 偏好层

礼物偏好不是单一物品表，而是“通用五档规则＋个人覆盖项”的组合：最爱、喜欢、一般、不喜欢、讨厌。个人规则优先于通用规则。

34 名居民的五档全集、中英文物品名和两处来源差异裁定见 [NPC礼物数据总览](../数值数据/NPC礼物数据总览.md)。

### 2.3 点数层

对话、送礼、任务、电影、节日、垃圾桶目击、弹弓、衰减和事件选择共同改变内部好感点。界面的心数只是点数的可视化，每心对应 250 点。

点数层还处理三个容易混淆的概念：

1. **可见心数上限**：普通村民 10 心、未送花束候选人 8 心、配偶或室友 14 心；
2. **内部点数上限**：允许在满心阈值之上保留 249 点隐藏缓冲；
3. **衰减停止条件**：普通关系在当前满心时停止，配偶和室友永不停止。

完整数值、公式和例外见 [NPC关系数值总览](../数值数据/NPC关系数值总览.md)。

### 2.4 状态层

关系状态决定上限和衰减速度：

```text
普通认识
  ├─ 不可恋爱村民 → 10心友谊
  ├─ 婚恋候选人 → 8心上限
  │    └─ 花束 → 交往中 → 10心
  │         ├─ 枯萎花束 → 分手并设为5心
  │         └─ 人鱼吊坠 → 订婚 → 3天后结婚 → 14心
  │              └─ 离婚 → 0心前任 → 记忆消除 → 可重新交往
  └─ 科罗布斯 → 10心 → 虚空幽灵吊坠 → 14心室友
       └─ 免费驱逐 → 前室友 → 记忆消除 → 可再次成为室友
```

## 三、日常互动循环

NPC 社交的基础循环由“寻找 NPC—交谈—选择礼物—维护关系”构成。日程决定玩家能否找到角色，礼物偏好决定送礼结果，点数规则决定关系变化，心数与状态再解锁房间、事件、恋爱和婚后内容。

系统刻意让不同互动渠道叠加：

- 交谈提供低成本、稳定的每日增益；
- 礼物提供更大的变化，并受偏好、品质、生日和节日影响；
- 求助任务、电影院、花舞节和社区中心提供阶段性增益；
- 未交谈、负面礼物、垃圾桶目击与弹弓提供关系损失；
- 《交友导论》提高所有正向增益，但不减轻负向损失。

这套结构让“知道角色在哪里”“知道角色喜欢什么”和“持续出现”同时成为社交玩法的一部分。

## 四、礼物系统如何计算

礼物计算顺序可概括为：

```text
通用偏好
  → 应用个人覆盖项
  → 得到五档偏好基础值
  → 生日/冬日星盛宴事件倍率
  → 最爱或喜欢礼物的品质倍率
  → 《交友导论》正向倍率
  → 当前配偶的关系变化缩放
  → 写入整数好感点并受状态上限约束
```

星之果茶走特殊规则：普通日固定提供一心的基础点数，不占每周礼物限制；生日或冬日星盛宴固定提供三心基础点数。具体数字和公式见 [关系数值文档第三章](../数值数据/NPC关系数值总览.md#三礼物点数与倍率全集)。

## 五、恋爱、婚姻与室友

### 5.1 恋爱

婚恋候选人在未送花束时停在 8 心可见上限。花束把关系切换为交往状态，开放第 9、10 心，并把每日未交谈衰减从普通候选人的规则切换为交往期规则。

枯萎花束不是普通负面礼物；它会直接结束恋爱，并把关系设置为 5 心。玩家仍可继续交谈、送礼并重新提升至 8 心。

### 5.2 婚姻

达到 10 心并满足农舍与海滩条件后，可用人鱼吊坠求婚。婚礼通常在求婚后第 3 天举行，婚后关系上限提高到 14 心。

婚后关系不是“达到满心后永久冻结”：配偶未被接触时每天仍会衰减。给曾接受花束的其他同性交往对象送非讨厌礼物，还可能触发配偶嫉妒。

### 5.3 科罗布斯室友

科罗布斯在 10 心后可通过虚空幽灵吊坠成为室友。室友关系大体采用婚姻结构，但没有婚礼、亲吻、嫉妒、子女和配偶农场事务；驱逐免费。科罗布斯的星之果实条件也与配偶不同。

完整费用、心数、概率、衰减与例外见 [关系数值文档第六至九章](../数值数据/NPC关系数值总览.md#六恋爱与分手状态转换)。

## 六、事件、日程与本文边界

爱心事件和 NPC 日程是独立的数据全集，不能用机制概述代替：

- 日程文档必须逐 NPC 收录季节、星期、天气、节日、婚后与特殊前置路线；
- 事件文档必须逐 NPC 收录心数、地点、时间、天气、前置、可错过性、所有选项和点数后果；
- 在这两份全集完成前，NPC 数据域仍保持“采集中”。

本文不再列举少量“关键 NPC”或“主要事件”，因为选择性示例会掩盖缺漏。后续数据文档完成后，本节将改为直接链接到逐人锚点。
