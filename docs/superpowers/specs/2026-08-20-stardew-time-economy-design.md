# 星露谷物语时间与经济文档联合重建设计

## 目标与范围

本批把《时间季节系统》和《经济系统》从历史分析稿重建为 PC v1.6.15 可审计资料页。完成条件不是文件大小，而是两页分别定义完整规则族、固定来源、预计/实际数量、字段边界和本地跳转；所有差异必须为 0。

时间页完整维护时间推进、暂停、睡眠触发、季节转换、年份变化、天气生成与固定日期。节日、角色精力、作物、鱼类和爷爷评分的对象数据不复制，必须跳转现有全集。

经济页完整维护货币与非金币进度资源的职责、出售渠道、价格计算顺序、品质与职业倍率、加工定价公式以及价格变化规则。作物、加工品、装备、建筑、节日库存、齐先生任务和出货收集槽位的逐对象数据不复制，必须跳转现有全集。

## 方案选择

采用时间/经济联合重建。两页共享季节、商店营业、加工计时、出货结算等边界，联合处理可以一次消除重复和冲突。

未采用“先时间后经济”：会保留阶段收益和季节建议的临时重复，并产生两轮导航审计。未采用“仅修明显错误”：无法证明全集和字段完整率，不符合 v2.9。

## 文件职责

- `牧场经营类/星露谷物语/机制分析/时间季节系统.md`：时间与天气规则的直接查询页。
- `牧场经营类/星露谷物语/机制分析/经济系统.md`：经济计算和结算规则的直接查询页。
- `牧场经营类/星露谷物语/游戏概览.md`：同步实际文件大小和状态。
- `采集策略/工具/审计星露谷全游戏导航.py`：更新两页真实表格/来源基线和非数值文档状态。
- `采集策略/审计记录/牧场经营类/星露谷物语.md`：记录预期、实际、差异、来源和测试证据。
- `采集策略/全库补全与导航重构计划.md`：推进下一未完成域。
- 已有跨域审计器：只在断言文字因职责边界改变时更新，不创建新脚本。

## 数据流与来源

1. 通过 MediaWiki API 读取指定页面的固定 revision，而不是读取会继续变化的当前页。
2. 从固定 revision 提取章节、表格和规则事实，形成来源预期集合。
3. 解析当前 Markdown 得到实际集合，先运行失败测试并保留缺失/残留清单。
4. 依据差异重建两页；每个数值都能追溯到固定来源或已验收本地数据页。
5. 再次解析文档，对比预期与实际，并运行全部现有星露谷审计器。

## 真实测试设计

真实测试不以“脚本里写了 10，文档里也写 10”作为唯一证据，而同时核验：

- 固定 revision API 的页面标题、revision ID 和原始章节存在。
- 来源中枚举的规则键或表格行，与文档中实际行逐项比较。
- 旧稿中的估算、推荐、错误版本和无固定来源链接必须命中失败，重建后为 0。
- 文档中的预计/实际数量必须由实际解析结果支持。
- 全游戏本地链接、锚点、上一篇/下一篇和概览顺序必须真实解析并为 0 断链。

红灯阶段预期：时间页缺少固定 revision 和完整天气/年份对账；经济页仍包含阶段日收入估算、推荐设备、总成本估算与当前页链接，因此测试失败。

绿灯阶段预期：来源集合差异 0、旧口径残留 0、未知值 0、全量审计全部通过。
