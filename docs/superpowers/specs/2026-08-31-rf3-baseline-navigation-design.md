# 符文工房3全游戏基线与导航重构设计

## 目标

为《符文工房3》建立 v2.9 的第一份可复现审计基线：厘清实际文件、版本范围、来源职责、重复数据域和连续导航。旧文档不因篇幅或历史标题继承“完成”状态；本批只把能够真实验收的结构闭合，九份数据文档继续保持采集中。

## 方案比较

1. 直接按旧概览的 23 篇逐篇扩写：速度快，但会永久漏掉现有《角色弧线深度解析》，也会继承“动物怪物/怪物”重叠域。
2. 一次性重写全部 24 篇内容文档：表面步数多，但九个全集的来源和字段互相依赖，无法保证每个红灯都来自真实差异。
3. 先闭合文件、版本、来源、归属和导航基线，再按数据域逐个完成全集。采用本方案。

方案 3 先消除结构不确定性，同时把旧稿中的“代表性”“推测”“约数”“需数据挖掘”显式记录为未完成证据。后续每个数据域仍遵循固定来源、预计条目数、实际条目数、字段完整率和差异归零。

## 本批范围

- 覆盖磁盘上的 1 份游戏概览和 24 份内容文档：机制 10、数值 9、特色 5。
- 将遗漏的《角色弧线深度解析》补入概览；README 文档数同步为 24。
- 所有 25 份游戏文档补齐顶部面包屑，24 份子文档按概览顺序补齐上一篇、返回概览、下一篇。
- 新建《符文工房3 v2.9 全量数据与导航审计记录》，记录版本、来源、九个数据域现状、重复归属和后续顺序。
- 新建一个基线审计器，检查文件集合、概览顺序、导航、数据覆盖声明现状、本地链接及计划/审计对齐。
- 不在本批为九份旧数据文档补造虚假的预计总数，不把任何仍含推测或节选的数据文档标记为已完成。

## 版本与来源边界

主基线为 Rune Factory 3 Special（Nintendo Switch / Windows，2023）。官方产品页用于发行平台、日期和 Special 新内容；Marvelous 官方在线手册用于农耕、合成、战斗、同伴与婚恋等规则边界。原 Nintendo DS 版本只在文档明确讨论差异时纳入，不把两个版本的数值默认混写。

官方手册是规则源，不是对象全集。作物、NPC、怪物、技能、节日、装备和配方的预计总数，后续必须另由完整列表、攻略本、可靠 Wiki 或游戏数据确定。

## 唯一归属

- 《动物怪物数据总览》暂定为“驯养与产出怪物”域；普通敌人、Boss、属性、掉落和区域名册归《怪物数据总览》。后续可在全集重建时按内容重命名，但本批先记录边界，不复制表格。
- 机制文档只解释规则和设计，完整对象表跳转数据文档。
- 《角色弧线深度解析》属于特色文档，必须出现在概览和连续导航中。

## 真实测试

- 来源绿灯：官方产品页与官方手册指定页面实际返回 HTTP 200，并包含对应页面标题或关键主题。
- 结构红灯：旧概览声明 23、实际内容 24；概览漏链 1；面包屑 0/25；连续导航 0/24；数据覆盖声明 0/9；审计记录不存在。
- 结构绿灯：声明、实际和概览均为 24；面包屑 25/25；连续导航 24/24；本地路径与锚点断链 0。
- 需求边界：九份数据文档状态全部为采集中；审计记录必须列出每份文档的缺口，不得因导航完成而宣称数据完成。

## 完成边界

本批完成只代表《符文工房3》的结构与审计基线完成，不代表整款游戏完成。全库计划继续把《符文工房3》标为采集中，下一批从数据全集来源最清晰的域开始红—绿补全。
