## 一、目标

对仓库内全部游戏和全部文档进行逐款重审，最终实现：

1. 数据相关文档覆盖目标维度的全部条目与全部规定字段，无选择性节选。
2. 所有数据能够追溯到明确版本和来源，关键表格具有来源映射。
3. 每份数据文档均有覆盖范围、预计条目数、实际条目数和字段完整率对账。
4. README、品类索引、游戏概览、子文档及相邻文档之间能够连续点击跳转。
5. 旧文档中的缺项、重复、过时版本、错误链接和模板化空壳全部得到处理。

## 二、完成状态定义

| 状态 | 定义 |
|------|------|
| 待审计 | 旧文档尚未按 v2.9 检查；无论历史评级如何，都不视为完成 |
| 采集中 | 已开始盘点或补全，但仍有缺项、待核实数据或导航问题 |
| 受阻 | 已穷尽常规来源，仍无法验证全集或关键字段；保留检索记录，不计入完成 |
| 已完成 | 全部文档通过数据、来源、版本、结构和导航五项验收 |

**文件大小不参与“已完成”判定。** KB 仅用于发现疑似空壳；只要遗漏一个应采条目、一个必填字段或一个内部链接，状态就不能是“已完成”。

## 三、单款游戏标准流程

### 1. 文件与导航盘点

- 枚举游戏目录中的全部实际文件。
- 对照品类策略确认应有的数据维度和特色维度。
- 检查品类索引、游戏概览和磁盘文件是否一一对应。
- 建立文档顺序，作为概览列表与上一篇/下一篇导航的唯一顺序。

### 2. 数据全集定义

- 为每份数据文档定义覆盖版本、平台、DLC、更新内容和排除边界。
- 使用官方资料、可信 Wiki、游戏内图鉴、攻略本或数据挖掘结果确定全集。
- 建立中文名、原名、稳定 ID 和版本名称映射，避免漏项与重复。
- 定义每类条目的全部必填字段。

### 3. 全量补全与对账

- 列出全集中的每一个条目，不使用“主要”“代表性”“等”代替余项。
- 填写每一个规定字段；未知值保留字段并进入待核实清单。
- 对每张表记录类别小计和总计。
- 对预计条目数与实际条目数进行对账，差异必须为 0。
- 核查基础版、DLC、更新、平台和地区差异。

### 4. 机制与数据互链

- 机制文档中的数字链接到对应完整数据表或表格锚点。
- 数据文档链接回相关机制解释。
- 跨游戏比较链接到仓库内已有对应文档；不存在时链接到其游戏概览或明确记录待建目标。

### 5. 导航重构

- 每篇文档顶部添加项目首页、品类索引、游戏概览面包屑。
- 每篇子文档底部添加上一篇、返回概览、下一篇。
- 游戏概览完整列出当前目录全部文档，并提供准确相对链接。
- 品类索引链接到游戏概览，README 链接到品类索引。
- 长文档建立目录和稳定锚点。

### 6. 最终验收

| 验收项 | 通过条件 |
|------|------|
| 数据 | 预计条目数 = 实际条目数；必填字段缺失数 = 0 |
| 来源 | 全文数字可追溯；来源冲突有记录和裁定依据 |
| 版本 | 基础版、DLC、更新及平台差异边界清楚 |
| 结构 | 概览与磁盘文件一一对应，无漏文档和幽灵链接 |
| 导航 | 内部链接、锚点、上一篇/下一篇全部有效 |
| 未决项 | “待补充”“待核实”和无法解释的未知值数量 = 0 |
