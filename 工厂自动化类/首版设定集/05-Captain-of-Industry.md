## 一、岛屿既是资源表，也是正在变化的工地

采矿、加工、人口食品、车辆与外贸共存于同一片可变地形。工厂规模并不只由解锁了多少机器决定，还由矿区巷道能否扩展、填筑是否吞掉交通走廊、居民所需的基础供给是否稳定共同决定。官方商品页给出的长线从初期冶金延伸到核电与太空；这表明进度具有层级，但商店的“100+ 科技”不是可作题库验收的准确对象全集。[商品页](https://store.steampowered.com/app/1594320/) · [官方定位](https://coigame.com/)

| 回路 | 输入与先决条件 | 混合压力 | 把问题变成可观察指标 |
| --- | --- | --- | --- |
| 采掘—排土 | 矿面、车辆、运输路径、可用卸点 | 货物不是纯矿，混料滞留和排土不当会阻断后续 | 同查挖掘队列、混料成分、接收端和卸料区许可 |
| 加工—运输 | 有效配方、供应源、路网与接收设备 | 严重依赖单一节点时，线路涨产只把拥堵推往下游 | 按配方拆统计，区分总生产和净流入 |
| 居民—产业 | 人工、食物，及扩展时逐步增加的基础网络 | 工厂拉走资源，居民与设备维护若同时缺供，恢复难度增大 | 分看人员、电力、维护与产物流图层 |
| 交通—地形 | 稳定路基、坡度、车站/目的地 | 一处坡道或双向终点可能影响整个干线 | 从速度限制图查坡度，从列车统计查阻塞 |
| 研究—空间尺度 | 初级加工支持工地，后续工业引入更长物流链 | 扩张越快，备援越需要覆盖工厂与矿区共同节点 | 标出哪些设备、资源和产线可独立恢复 |

表中“恢复难度”“完善统计”等为设计分析。4.3 提供可分维度观察的叠加层，4.2 日志确认了按配方区分产出与消耗的统计；建议使用这些工具观测，而不是把表中任何推断当成固定游戏公式。[4.3 信息叠加层](https://coigame.com/Blog/update4-3-is-out) · [4.2 配方统计](https://coigame.com/Blog/update42-is-out)

## 二、4.3 混料机制：物流运的是组成，不是一种新纯矿

矿车把混合物送进指定接收仓，在满足许可时也能从仓送去倾倒；仓、传送带和火车都能沿链传递混料。分选厂增加皮带入料，可只分出所需品，把其余成分保留在混料出口。未选择的组成没有凭空消失：倘若没有可靠的余料出口，保留成分可能把分选端变为瓶颈。官方还说明混料仓被指派到矿塔时，仓满后对应卡车会等待而不是改去其他点。[4.3 混料机制](https://coigame.com/Blog/update4-3-is-out)

| 场景 | 规则或约束 | 适合观察什么 |
| --- | --- | --- |
| 混矿进仓 | 指派矿塔后可接收混合卡车货；仓满则车辆等待 | 仓位与矿区车辆等待是否同向变化 |
| 分选厂先抽目标物 | 皮带可进，未选成分可作为混料继续出厂 | 对照入料成分与目标品、混料副产两路的变化 |
| 从仓向填筑区卸混料 | 区域必须允许混料里的每一种产品 | 区域只许部分成分时，不把拒卸错判成卡车故障 |
| 混料重新使用 | 堆料机可处理此类倾倒，混料专用仓和车站也可接收非混料 | 确认数据表标明允许接收的类别与实际载荷类别 |
| 回收物 | 记录来自什么产品，分选产出对应废料，不再按全厂平均构成 | 重点记录入料来源、有无混合、实际废料种类 |

**案例：同一批混采料先服务有需求的生产链，再处理余料。** 将主产品产线不畅与余料出口拥堵作为两个假设：前者检查有用产出是否达到生产需要，后者核查混料组成、剩余容量和卸区许可。一次只改一个输入条件，复查等待车辆和两路库存。不要把在开放场景观察到的可处理性套到对成分有限制的弃料区，也不要从官网机制硬凑比例。本案例是按公告设计的复核，不是已测的生产图。

**热修区别。** 2026-11-06 的 0.8.8c 改善回收产出塞满时的处理：机器可以继续跑其他配方，维护站能用不产回收物的配方退回运行，粉碎机也可回退到其他无回收物配方；这不是通用的“所有副产满仓都不停产”。[官方热修汇总](https://coigame.com/Changelog)

## 三、铁路、车道与具象瓶颈

Update 4.1 加入基于运输任务的列车网，包括保留容量、等候设施和专用补给；连接储存可扩展站容量。到了 4.3，列车有工作、空闲、加油和不工作的活动统计，并细分站间运行的全速、加减速、轨道限速、被挡时间。不同类别对症解决，而不是普遍加列车：站口阻塞不一定靠多发车缓解，陡坡限速也不能通过增加仓容解决。[已发布的 4.1 条目](https://coigame.com/Roadmap) · [4.3 铁路统计](https://coigame.com/Blog/update4-3-is-out)

| 公开参数 | 快照事实 | 限界 |
| --- | --- | --- |
| 模块化道路坡道 | 4.2 支持 1 或 2 层高，长度可变，车辆可驶过 | 不是所有桥梁和载具的通过率；货物许可还要另算 |
| 通用车厢 | 4.2 的 T1/T2 通用车型可载不同类别产品，相应容量为专用车型的 3/4 | 不是整个网络吞吐的 75%，不将历史改动无条件外推 |
| 轨道坡度 | 4.3 的 25% 坡（含过渡）限速 80 km/h | 公告提及 12% 较缓坡作对照，未宣告其时速 |
| 屏蔽车站模块 | v0.8.8a 将模块转移速率从 306 调为 300 产品/分钟 | 模块速率不等于车厢容量、列车速度或整站吞吐 |

来源：[4.2 开发者说明](https://coigame.com/Blog/update42-is-out) · [4.3 官方热修](https://coigame.com/Changelog)。4.3 屏蔽车厢和站点模块用于运输游戏中的放射性物料；此作按建筑、车载、皮带实际持有的相关物料逐日算辐射。这里记录的是游戏状态模型，不将其解释为现实工序。

### 铁路预约与仓库实连

4.1／v0.8.3 引入自动列车网络：货站负责装卸，燃料站负责补给，等候位承接空闲列车。每次派车会在装货站预留货物，在卸货站预留空位，避免两车同时把同一批货或同一份容量当成可用。来车也计入按货品设置的到站条件；开启「完整服务」时，要求站能装或卸完整列车。网络的需求阈值、优先级与固定时刻表线路分别设置。卸货站达到主动请求的阈值后，只要确实有空间，仍可能接收正被匹配装货站主动发出的货，因此阈值不是仓容硬上限。[MaFi 4.1 说明](https://coigame.com/Blog/update41-is-out) · [4.1 更新记录](https://coigame.com/Changelog/0.8.3)。

**界面记账与货物流动是两回事。** 仓库直接接在站台模块的端口上时会自动计入；使用手动指派工具关联的仓库也算入到站容量，但仍须铺通对应皮带或管道。若只指派、未实连，系统会按额外空位派车，物料却不能进入那座仓。另一方面，同货品的站台模块会内部均衡。MaFi 举例：三节车厢的末节还差 50 件，货在已装满的第一节对应的站台模块；同站模块均衡可补上这 50 件。它能解决站内货在错误模块的问题，不能替代外部仓接线，亦不保证任意吞吐。[MaFi 的仓库连接与三车厢示例](https://coigame.com/Blog/update41-is-out)。

| 三组对照 | 调度可见总空位 | 第一单预约 100 后的账面余量 | 先不外送、等可用皮带充分转运后的预期 |
| --- | ---: | ---: | --- |
| 只有站台，初始空位 100 | 100 | 0 | 第二个 100 的完整预约不成立 |
| 原站台加一座同货品仓，另有 100 空位且实连 | 200 | 100 | 两单可成立，实际共可接收 200 |
| 同一座仓计入站台，但外部皮带未建 | 200 | 100 | 两单可成立，而可达空位只有 100；至少有一部分货无法卸完 |

这是容量账本推演，100 不是某类车厢的标称容量。固定同一普通单品、相同编组、足够起点库存，确保车站需求、路线、等候位和完整服务条件许可两单。以实际车厢和模块容量替代示意值，记录派车顺序、在途货量、每节车厢余货、站台和外仓的库存。第三组只补实连再做一次对照，不改阈值或车数。先在没有其他出口消耗的短样本做容量对照，再开启下游记录单位时间流量。轨道是否被车阻挡、车辆空闲及正在装卸，用 4.3 检视器分开看。[4.3 列车统计](https://coigame.com/Blog/update4-3-is-out)。

**版本对照。** 4.3 修正无任务但有剩货的网络列车：选择有空间的最高优先级站，而不再只找空位最多的站。官方也修正了相邻任务的取货点恰为刚卸货或加油的站时，列车可能空驶去交付的问题。这两项不是 4.1 首发规则。上述容量对照用普通单品，不和 4.3 混料分类一起改。[4.3 补丁记录](https://coigame.com/Changelog/0.8.8)。

### 用本地数据给复测留证据

4.3 的内置 Web API 提供只读游戏信息、产品目录、产品统计与历史、生产来源等。复测时只在隔离的本地测试实例查当前版本的 `/routes` 或 `/demo-dashboard`，留存版本元数据、产品 ID 和同一时段的一份历史，再和站台、车厢库存截图配对。产量历史能反映前后变化，但不能证明某单具体预约了多少；官方所列只读接口未证实能读出铁路预约，仍需用界面记录。无需开放跨来源访问或调用写入命令；本文没有访问实机、读取用户存档或采集数据。[MaFi 的 API 发布说明](https://coigame.com/Changelog/0.8.8)。

## 四、设计启发：让玩家知道堵在哪，以及为什么

- **混料的中间态可见。** 检视选中的储存、卡车、车厢，可看内部组分；游戏内 Codex 也提供混料和产品的双向关系。与其每次让玩家拆厂猜测，界面应允许他找出究竟是哪一成分阻断了整体。[4.3 混料说明](https://coigame.com/Blog/update4-3-is-out)
- **地形改造应长期改变物流结构。** 矿区、车流、可卸位置、坡度起伏是一组持久约束：此处做错即使可拆，也会改变旧路的价值。可拆分“服务道路”和“干线”，有意把短期工程延伸与全局流动隔开；这是设计启发，不是官方推荐模板。[官网](https://coigame.com/) · [官方坡道设计](https://coigame.com/Blog/update42-is-out)
- **分状态而不是给单一总分。** 电力、计算、维护叠加层可看当前或长期平均；流图看特定产品生产与消耗。依赖链停顿时，把玩家要排的“为什么现在断了”和“是否一直负产能”区分是有效的信息设计。[4.3 信息叠加层](https://coigame.com/Blog/update4-3-is-out)

## 五、验收边界与下一步

本批只整理公开的玩法边界和版本差异，没有触碰用户存档、运行游戏或给出数值全集。官方托管 [Wiki](https://wiki.coigame.com/)由社区维护，主页标明配方曾从 Update 3 导入；不能用旧库校写 4.3 现行数据。正式补库时固定 v0.8.8d、地图、模组/DLC 与难度，从游戏内 Codex 或官方公布的只读产品目录分别核对产品 ID、配方、处理设备、单周期耗时和单位。测试南北不同卸区接收相同混料、分选出口满仓、0.8.8c 回退和同列车不同坡度；补齐前不宣称覆盖全市场、全科技、铁路能力表或全部污染与维护公式。[官方路线图（仅用已发布板块）](https://coigame.com/Roadmap)
