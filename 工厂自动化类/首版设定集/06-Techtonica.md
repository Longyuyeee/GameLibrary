## 一、工厂扩展同时是地下路径的扩展

玩家以第一人称在 Calyx 地下探索、挖掘可破坏地形、建立工厂并推进有完整配音的故事。洞室不是单纯背景：开路、加工位置、回厂与新区域供给会相互影响。初期通道可先解决人能否到达，之后还要解决物料和电力怎么通达；解开地图的同时，需要把临时引导路径变成可以持续使用的生产路径。[游戏定位](https://store.steampowered.com/app/1457320/) · [完整 1.0 日志](https://techtonicagame.com/techtonica-1-0-going-up-out-today-34-off-for-launch-week/)

| 阶段 | 主要活动 | 会积累的后续能力 |
| --- | --- | --- |
| 找到可用空间 | 探洞、定位资源、开出可达工作区 | 将工具与探索情报转成可建区域，而不只是地图完成率 |
| 搭最小生产 | 钻采、熔炼、输送、装配，引入电力或燃料 | 第一次形成持续补货，减少手动跑动 |
| 采集并投入研究 | 找碎片、升级驱动、核心，用技术树刷新选择 | 加工与移动能力一起变强，不只叠乘产量 |
| 将供应分层 | 通过货运电梯跨楼层送物料和电力 | 旧厂有机会继续给新工区供货，不必自动判废 |
| 沙漠工程 | 用耗燃料的抽沙设备处理沙海，部署粉碎机与新材 | 扩展空间本身需要可持续的燃料和维护物流 |

以上是根据公开系统组织的设计循环，不是逐级任务清单，也不先行揭露剧情。

## 二、用货运电梯改变“下一层”的依赖关系

1.0 把地图拆分为可探索和工业化的 **16 层，11 层河流区加 5 层沙漠区**；货运电梯同时支持物料和电力的跨层传递。这个数字来自开发者发布说明，不来自地图编号的猜测；同页宣称全可探索面积约翻倍，是与更新前比较的官方概述，不用来计算各楼层面积。[1.0 地图及物流说明](https://techtonicagame.com/techtonica-1-0-going-up-out-today-34-off-for-launch-week/)

**案例：旧楼层供基础材料，新楼层建抽沙与处置。** 电梯端口把“有路”和“线上有货”分开。先在不启用扩建负载的情况下记载是否能给新层持续供应基础物料和电；再观察燃料投给抽沙泵后，供给变动如何影响空间进展。需要的假设是：一旦旧厂/电梯/燃料任一环节低于需求，耦合的建设回路会放慢。这里是依据一手机制制定的对照，非已实测的电梯速率，也不假设所有楼层接口/容量相同。

| 检查对象 | 生产视角下的问题 | 应记录的证据 |
| --- | --- | --- |
| 楼层入口 | 人能到，电与材料是否已走通？ | 分别确认角色通行、到货、用电设备状态 |
| 电梯物料接口 | 是源层没投料、目的层没接货，还是搬运不足？ | 两端同窗读取库存变化；不拿动画瞬时判断吞吐 |
| 沙海设备 | 能否把探路持续到下一个目标区？ | 记楼层、泵的开停、燃料、前后可达区域 |
| 返程物流 | 新资源回旧厂会不会阻断原本向上供给？ | 将出发层、到达层、材料方向和该层消耗分列 |
| 服务路径 | 地形或净空受限时，玩家还能不能巡视链路？ | 记录步行、悬浮/喷气设备到达的对照，不写成固定净空值 |

没有来源支持所有电梯层的进口、出口和功率上限。后续数值表需在同一发布构建内以实际工具提示和独立采样核对。

## 三、沙漠和研究如何同生产形成闭环

沙海扩张不是静态资源加总。抽沙泵会消耗较多燃料；粉碎机能加工或拆分若干物料，并可在特定投入下发电。新增 Sesamite、Scrap Ore、Carbon Veins 等进料，与新的流程共同嵌入沙漠。官方还说明部分循环改用粉碎机、可处理废矿回收高级零件。仅说清连接关系，不用“循环”二字推定自供、净正收益或具体配比。[开发者 1.0：机器与配方](https://techtonicagame.com/techtonica-1-0-going-up-out-today-34-off-for-launch-week/)

| 1.0 发布说明中的参数 | 前后或实际范围 | 不能从这里推出的结论 |
| --- | --- | --- |
| MKII 装配器 | 公布每份配方产出倍率从 2× 调到 4× | 实际分钟产出还依赖节拍；同一发行说明列有某个末期物品仍只出单件的已知问题，不能宣称所有对象都翻倍。 |
| 摇柄发电机 | 公布基础持续 5 → 10 分钟；与 CrankSpan 可叠加 | 不等于发电功率翻倍，不推断未公开的叠加运算。 |
| Research Core | 公布占地从 2×2 改成 1×1，新增绿、黄核心 | 不等于同体积研究进度必为四倍；排列、技术和限制另核。 |
| Core Composer | 公告列 2k、4k、8k 三种，建造时预留核心空间 | 保存官方型名；不把数字直接当作实测容量、三个解锁等级或性能公式。 |
| Core Boost | 1.0 的重做方案以末期黄色核心为对象 | 不把颜色数据外推成旧版其他颜色仍可使用同样加成。 |

来源：[1.0 完整日志的 Highlighted Changes、Machines、Tech Tree 与 Known Issues](https://techtonicagame.com/techtonica-1-0-going-up-out-today-34-off-for-launch-week/)。官方宣称 40+ 新配方、25+ 新中间物；这两个量都是发版新增概数，不是本体的完成分母。

**研究和探索是同一串决策。** 1.0 重做 Omniseeker，公开说明能跟踪矿物、碎片、升级驱动和隐藏箱，并显示距离与方向；Hoverpack 的喷气升级又扩大可达性。把探测提示和行动工具前后串起来，玩家拿到的不只是“增加跑速”，而是观察地图后可采取的新行动。把研究核心放置和生产设备拆表，记录“得知目标 → 可以到达 → 可以开采 → 可以持续供料”，才不至于把探索当成长系统的噪声。[开发者 1.0：Tools 与 Tech Tree](https://techtonicagame.com/techtonica-1-0-going-up-out-today-34-off-for-launch-week/)

## 四、同类设计比较：空间既是内容也是成本

- **和 Satisfactory 比：** 两者都能让玩家亲自浏览工厂，但 Techtonica 明确将可破坏地下地形和跨层电梯作为逐步拓展的约束；Satisfactory 官方强调外星地表探索和第一人称工厂，两者的空间排障入口不同。若参考前者，可先测试一条隧道的通行是否同时对建造、运货和供电有不同要求；不要为了地下主题塞入纯装饰障碍。[Satisfactory 商品页](https://store.steampowered.com/app/526870/) · [Techtonica 商品页](https://store.steampowered.com/app/1457320/)
- **跨层边界应有清晰证据。** 普通出货、设备状态、电力和剧情门槛分开显示，比“本层未解锁”更利于排障；上下层甚至可以拥有不同的维护责任，而保持同一份接口契约。这是从电梯、工具和地图设计提炼出的建议，并非官方指出某个 UI 一定存在。
- **公告的多人范围不是每平台合同。** 1.0 公告描述最多 4 人合作，同时在 PS5 专节明确不支持多人。资料台账应至少分 PC、Xbox、PS5，遇到人数或功能冲突优先读取平台限定，不由描述性营销语推断所有版本。[发布公告与 PS5 限定](https://techtonicagame.com/techtonica-1-0-going-up-out-today-34-off-for-launch-week/)

## 五、验收边界与下一步

没有运行实机或读取存档，不承诺 16 层名字、开通顺序、全菜单数据、全配方、独家新机器清单或所有线上模式状态。建议首轮真实样本只选一个 Steam 1.0 构建：录一条跨层供电、物料往返与抽沙泵用量；另测普通与末期物品的 MKII 倍率，记录分母、时长、输入不足或输出堵塞。逐配方整理输入/输出/耗时、机种档次、持续功率/燃料、解锁条件与固有例外，同时按平台保留版本字段。官方 Steam 转载与开发者网站为同一声明，现场数据才能新增独立证据。
