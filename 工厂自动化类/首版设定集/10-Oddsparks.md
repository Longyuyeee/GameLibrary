## 1. 生产对象本身也是运力

Massive Miniteam 把村庄任务、野外探索与自动化接成循环。玩家带 Spark 外出，前往不同群系发现资源、遗迹和敌人；新产物带回村庄，解锁工坊和物流设施；工坊又能制造更多 Sparks 和装备，帮助进入更远的新区域。商店明确指出不依赖传送带：Spark 会在路网中携物、参与制作，并受到同路交通、距离和高程的约束。[store]

| 对象 | 玩家的直接控制 | 与工厂比较有关的边界 |
| --- | --- | --- |
| 角色及 Sparks | 探索、选择有用的同伴、配置它们承担作业 | 闲置同伴不等于空运输带；调去战斗或另一工坊会改变本线路的供给 |
| 工坊 | 生产材料、成品或更多 Sparks，安排取放与衔接 | 界面配方秒数不等于加上等待后送到终点的平均秒数 |
| 路网 | 规划路径、分叉、筛选点和等待/放行工具 | 交通的主要压力是单位移动、路口和等候，而不只是建筑加工速率 |
| 高架列车 | 跨长距离和高程运输，选择跨区线路和车辆 | 运力随栈容量、路线和站点情况变化；高架并不自动修复地面取货堵塞 |
| 村庄与遗迹 | 交任务学新建筑、探索生物群系、解锁古代遗迹信息 | 任务层级、故事、群系地形是不同解锁轴，不由一个编号概括 |

## 2. 从局部工坊到长距离组织

1. **先在附近闭环。** 确认资源能被指定单位取到、工坊收料且有成品被带走。第一次尽量只给单一任务，便于分清「工坊没做」和「做完但未配送」。
2. **按任务增长改进物流。** 村民任务驱动新设施。新类型的 Sparks 和路线规则提供额外控制，但把更多运输单位塞进同一路段也可能增加等待。记录任务所需交付与材料回流，避免只优化单机出产。
3. **跨区与高差。** 官方将高架 Spark 列车作为长距离及高程解决方案。地面仍需要从工坊把材料送站，再从另一端分发。比较改造效果时应计入上下游转运，而非只测车站间行驶。
4. **可见与可控。** 1.0 加入升级后的地图视图，显示列车 ID、颜色与燃料状态，后续解锁远程管理，可以从地图调整部分模式或补燃料，不能替代建、拆、移建筑。控制面优化的目的是减少巡检，从地图定位错误后仍可能要回现场修建。[r1]
5. **终局回收旧技能。** Corrupted Ruins 是发布公告中的最终群系，最后一批为 Tier 10 任务，完成后进入终局自动化挑战。官方描述洞内目标需要基地外的产能配合；本篇不补写最终配方和剧情结局。[r1]

## 3. 1.0 可核验的核心机制

| 条目 | 一手已知 | 不从公告外推 |
| --- | --- | --- |
| Spark Filter / Item Filter | 1.0 加入逆向筛选；空物品筛选的原例允许空载单位，反向则让有货单位通过 | 不猜多条件组合优先级或不存在的白名单格式 |
| Amount Filter | 支持特定数量以及大于等于、小于等于的比较模式 | 模式不是本篇证明所有整数范围和分流公式 |
| Spark Gate | 末期与逻辑工具组合，Spark 排队，接到信号才放行 | 脉冲长度、重复信号、满队列行为需复测 |
| 配方显示 | 术语表显示配方耗时和每分钟件数，可改显示小数精度 | 显示精度不能说明模拟内部精度 |
| Big Cargo Wagon | 一种物品可装 10 栈；普通车厢可携多种物品、总计 6 栈；公告强调取舍 | 10 与 6 是栈数，不等于每栈件数、运输速率或满载概率 |
| 联机 | 商店列出官方支持到 4 名玩家且不设该硬上限 | 不是支持任意人数无条件稳定，也不证明 PS5、Xbox 或跨平台情况 |
| Enemy Sensor | 检测敌人与腐化，可调角度和长度，玩偶可限定检测敌类 | 摘要未给数值范围、遮挡方式和信号保持时间 |
| Spark Cannon | 四种目标类别：敌人、可采集物、腐化、掉落物；公告说明以逻辑关闭可唤回 Sparks | 不是任意目标都可使用同一类 Spark，也不填冷却范围 |
| 世界设定 | 发布时说明分 5 类，调配方速度、燃料燃烧、掉落、价格、推进、地形或战斗；任务道具系数可设到 4 倍 | 4 倍不是 Default；沙盒无费用亦非默认配方，不能在不同预设之间直接移植数据 |

1.0 机制和变更来自[开发者发布正文][r1]；合作与基础机制来自[正式商店][store]。如果不同 PC 平台或后续版世界设置得出不同结果，保留两个版本下的证据，不回填成同一条默认值。

## 4. 防御如何接入工厂

Corrupted Ruins 的基地产生被攻击风险，Hostility Overlay 可用来查看危险区域。开发公告给出一种基于单位分工的玩法：以 Burning 处理敌对目标，Stumpy 拾取掉落，Scrubby 处理腐化，三个任务可用炮台目标模式分工。能感知、能派出、能收回是不同控制阶段；需要照看工厂的物品流和 Spark 的用量。公告还提到 Animal Scarer 可调整产生威胁的节奏，不把此工具的可见效果当生物群系刷新率的量化规则。[r1]

**设计分析：** 这使「防御」变成一条会占资源、产生残余任务并反馈路线的生产线。只比较消灭敌人的速度会遗漏收集和清理成为瓶颈的情况。可在同一设定中对照：从传感器有输出开始，标记敌对目标解除、物品抵达工坊、腐化清除和单位归队四个时点。没有录制对照前，不宣称必须把三类单位固定为任何数量。

## 5. 物流与配方：量化的正确方法（推导）

- 单一货物、两种车厢都满载且来回等时间时，10 对 6 栈约为 **1.67 倍标称载量**。这是该条件下的算术对照，非游戏吞吐加成；只要一个车厢混装、站点堵塞、栈未满或两条路线的周期不同，就不能套用结论。
- 观察「零散品类共发」时，普通车厢的 6 栈可以用于多个货物；在货量大的单品路线上，10 栈车厢的选择才以分配代价换来优势。记录栈种类、每栈单位数、发车时的实载、往返及始末站停顿，分开比较容量上限和实际到货。
- 收集默认配方时使用 Default 存档并记录相关设置；在 Automation Focus、Sandbox、Hard Mode 或自定义存档中得到的吞吐、费用与解锁记录只能单列。若耗时或燃烧设置一并变化，勿把差异归因给机器人升级。
- 开发者提供可关闭强制精确时间步的设置；公告中另有默认时间预算值。性能参数可能改变处理时序，跨设备压测需保留此开关，但不能将每帧 CPU 预算、游戏配方时间与现实速率归为同一字段。[r1]

## 6. 可借鉴的关键取舍

**把探索奖励做成改造网络的选择。** 新群系不是只给新外观，它让玩家面对距离、高差与新用工方式，在「原线路多雇 Spark」和「用更高层的路线控制」之间选择。若做类似设计，地图应帮助判断负载发生在何处，让实体运输生动而不只是难调。

**把新手友好和数据可比性同时保住。** 默认路线对想按任务探索的玩家保留引导；可选预设及自动化前置可减少重跑。代价是同一个配方可能处于不同的世界规则。文档需要把影响时间或物价的开关写入记录主键，而不是只写「1.0」。

## 7. 缺口和下次验收方法

- 以 Steam 1.0 Default、无模组开档，记构建与种子，收集 Sparks 类型、基础原料、工坊配方、任务、群系、敌人和科技解锁的完整索引。
- 取一条实际工坊链和一条高差路线，保留工坊面板、路径附加物配置、运输对象载量和完整周期的连续录像，不缩成一张最佳表现截图。
- 对入口逆向筛选、Amount Filter、Spark Gate 各做一个正反例，记空载/满载、失败条件和条件是否为对应首发版；不要套用后续 splitter beta 的行为。
- 防御、列车与逻辑的设备速率、信号范围、配方需求、火力及伤害抗性尚没有全集，逐项保留待采；Workshop、Deluxe、付费列车扩展和测试分支分档。
